# Issue #20：移动端宽屏信息流分屏

针对 https://github.com/NihilDigit/piko/issues/20，基于 main 的 30c44c0706cf3d94a8b7846d5b49f34cc5d0f737。

## 实现

- `panelFits` 改用 `feedPanelFits`：两端均用 `sidePanelFits` 检查实际内容区宽度；移动端另检查内容区高度至少 480dp。
  主区 440dp、间隔 24dp、信息流最小 360dp、尾边距 16dp，共需 840dp。宽度来自 NavigationSuiteScaffold 内部的
  `onSizeChanged`，已扣除 Rail；不能以整个窗口达到 840dp 判断。高度也取同一测量结果。
- `feedFrame` 复用现有 `SidePanelLayout`，保持拖宽、宽度保存、最小主区宽度、系统栏避让与关闭入口。
  已保存的宽度由 SidePanelLayout 限制在可用范围内，不拿保存值决定能否分屏。内容区未测量时不分屏。
  启动恢复仍仅在能分屏且账号允许重开时生效；旋转和多窗口缩放只改变呈现，不清空会话。
- `FormFactor.Mobile` 不变：仍是三项导航（窄窗口底栏、更宽 Rail）、移动端目录标题、条目更多按钮、长按多选、任务 sheet。
  不启用桌面标签、命令栏、属性浮窗或桌面右键专属入口。`addLinkDocked` 另保留 desktop 条件，防止移动端同时出现右栏和任务 sheet。
- 返回：全屏信息流保留原来的关闭行为；移动端分屏的兜底 BackHandler 登记在网盘内容之前，
  让网盘的弹层、搜索、多选、目录返回优先，根目录再返回才关闭信息流。桌面 Esc 保持原行为。
  信息流的锁定横屏返回仍由 ClipFeedScreen 优先处理。
- TaskSlot 保持移动端排他，不按能否分屏放开。移动端信息流开着或挂起都占用任务位；
  打开添加链接或查重先确认结束信息流，取消保留会话。反向打开信息流仍经原来的 claim 确认结束任务。
  切到传输和「我的」保留信息流，不当成新任务。
- 浏览范围仍固定在打开时的文件夹：进入子目录继续刷，离开该树挂起；「在网盘中显示」挂起并记出发位置，
  「继续刷」经 returnTo 回原处，移动端不开临时标签。关闭才调用 ClipFeedSession.close；账号切换仍沿用 endAccount。

## 播放器会话

保留原来的 feedInPanel / feedFullScreen 互斥。FeedContent 仅在 visible、feedOpened、onHome 同时满足时组合 ClipFeedScreen，
退出动画里旧容器改画黑底，避免旧形态仍在播放。「看完整」压栈后 onHome 为 false，信息流停止组合，
PreviewBackend 经 onDispose 释放；ClipFeedSession 的队列、currentIndex、streams 保留，返回重新创建播放器。
切换分屏与全屏会重建播放器池，可能有重新出首帧的停顿；本次没有增加另一套播放器生命周期。
具体播放位置能否精确续上、动画交界是否出现音频重叠，需要设备冒烟验证，纯函数单测不证明这些行为。

## 自动回归

`ui/src/desktopTest/kotlin/dev/piko/ui/FeedLayoutTest.kt` 覆盖：

- 未测量尺寸、839/840dp 宽、479/480dp 高、宽而矮的手机、扣除 Rail 后不足宽度、普通手机。
- 桌面仍只看宽度，不因高度小于 480dp 失去侧栏。
- 横竖屏和多窗口尺寸序列的布局判断；开关、挂起状态在移动与桌面的任务占用规则。
- 信息流开着/挂起时开启添加链接或查重：取消不结束会话，确认先结束再启动；反向冲突同样确认。

命令：

```bash
./gradlew :ui:desktopTest --tests '*FeedLayoutTest*'
./gradlew :app:compileDebugKotlin
./gradlew :desktopApp:compileKotlinDesktop
```

本环境已通过 `git diff --check`。以上单测与两端编译均尝试运行，但 Gradle wrapper 下载 9.6.1 时因网络不可达失败，
没有进入编译或测试阶段，不能标记为通过。

| 场景 | 应验证的结果 |
| --- | --- |
| 平板横屏，内容区至少 840×480dp | Rail、触控操作和网盘列表保留，右侧持续自动翻信息流；进入子目录不更换队列 |
| 平板竖屏 / Android 分屏窗口收窄 / 高度降到 479dp | 信息流切全屏、盖住导航；拉宽且升高后恢复并排，同一 root 和 currentIndex |
| 拖宽右栏与重新启动 | 主区不小于 440dp；保存宽度受当前窗口上限约束；仅适合分屏时恢复打开 |
| 分屏返回 | 操作面板、搜索、多选、子目录优先返回；离开信息流根文件夹挂起；网盘根目录兜底关闭信息流 |
| 全屏返回 / 横屏锁定返回 | 全屏关闭信息流；锁定横屏先解除锁定，后续返回按当前形态处理 |
| 添加链接、查重与信息流相互开启 | 一次确认；取消保留原任务与队列，确认先结束原任务；添加链接始终只有移动端 sheet |
| 切传输或「我的」再回文件页 | 离开时无信息流音频，回来仍是原会话，不重复 open 或关闭队列 |
| 「在网盘中显示」后继续刷 | 信息流挂起，显示 FeedResumeBar；继续回原位置与历史，不增加桌面标签 |
| 分屏 ↔ 全屏动画 / 看完整后返回 | 任一时刻只有当前呈现拥有活动播放器；旧 backend 释放，无双音频；返回队列、段索引保留 |
| 切账号、退出登录 | 旧账号信息流和播放器结束，新账号不按旧开关自动重开 |
| 桌面宽窄窗口与添加链接 | 原有右栏让位、挂起、入口置灰、拖宽、独立窗口及 Esc 规则保持 |
