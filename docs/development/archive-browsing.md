# 压缩包当文件夹与目录图

状态：两项都已实现，约定见网盘页的 CLAUDE.md（`ArchiveBrowser`、`FolderMap.kt`）。

目录图与原方案的出入：快捷键（Ctrl+Shift+E，照 VS Code 的资源管理器）在宽窗口里钉出以根目录为根的卡片，不弹菜单，
菜单要锚在地址栏的某一段上；窄窗口不从面包屑召出，改为顶栏一个按钮开底部面板，面包屑那一行已经放满。
压缩包要密码时不在节点下就地输，点那一行进到包里，由网盘页原有的密码框问。

实现与原方案的两处出入：

- 包内文件没有走 `getArchiveTreeFile` 的直链，而是与归档条目一样按 gcid 借对象：引导解压之后 `listArchive` 给出各项的 gcid，
  按它秒传，包里从没解压出来过的文件也借得出来，字节一致（同一探针实测）。这样播放、下载与预览整套照用，不必另接一种直链与 token。
- 密码：浏览时先逐个试存过的再弹框。解压不这样做，那边每试一次是一个真实的解压任务；列目录只是一次查询。

## 压缩包当文件夹

单击压缩包是进去浏览，不再开始下载；下载移进操作菜单。

- 位置：压缩包是路径栈上的一级，照「库」的做法带前缀：`piko-archive:<文件ID>`，包内子目录为
  `piko-archive:<文件ID>:<包内路径>`。后退、面包屑、地址栏与标签因此照常工作。
- 加载：`DriveScreenState.load` 认出前缀后改用 SDK 的 `listArchive` 逐层列出，条目转成 `FileStat`，列表、网格与详情栏不改。
  每层的结果在网盘页的寿命里缓存。
- 存盘：上次位置与标签存到压缩包这一级为止，不存包内位置。恢复包内位置需要密码，不值得为此弹窗。
- 密码：先逐个试 `ArchivePasswordVault` 记着的，都不对再弹 `ArchivePasswordDialog`。试中的密码在本次会话里按压缩包记住。
- 分卷：服务端读不了，列表显示错误态并给出「下载」。
- 包内只读：不能新建、上传、粘贴、拖放、重命名、移动、删除、星标与归档；不解析、不折叠。
  能做的是多选后「解压选中」（`decompressArchive(paths)`）与主操作「全部解压」，任务照旧进 `ArchiveExtractSession`。

### 打开包内文件

包解压过时，服务端有包内文件树（`FileStat.archiveTree`），`getArchiveTreeFile` 直接给出该条目的直链。
没解压过的包没有这棵树，做法与归档的借出相同：

1. 把包内最小的文件解压到 Piko-Temp（`decompressArchive(paths = [它], toParentId = Piko-Temp)`），只为让服务端建出树。
2. 重读压缩包详情取树；没有就再解压一次同一项。
3. 彻底删除解压出来的东西，再用 `getArchiveTreeFile` 取所点条目的直链，交给播放、预览或下载。

之后这个包里的其他文件直接走第 3 步。实测（2026-10-05，`pikpak-kotlin` 的 `ArchiveLeaseProbeTest`）：

- 树覆盖整个包，不只解压出来的那一项。
- 解压出来的副本彻底删除后，树仍在，条目仍能列出，直链对 Range 请求回 206，字节一致。
- 第一次解压不一定出树：11 个新包里有 6 个在解压完成 11 到 99 秒后仍没有；接着再解压一次，5 次都在 200ms 内出现。
- 每次读到的 token 不同，用最近一次的。
- 会员账号上 `cloud_download` 次数没有变化。

未测：免费账号能否使用解压服务、是否扣某种每日次数（会消耗免费账号次数的实验须先问）。

## 目录图

照 VS Code 的 minimap：按需召出的浮层，不常驻占一栏，因此不改侧边栏宽度，也不在侧边栏旁边再开一栏导航。

- 召出：地址栏每段旁的 ›，在该段下浮出以它为根的树，展开到当前位置并亮起；另有快捷键从网盘根召出（键位待定，主修饰键+K 已是命令面板）。
- 内容：只列文件夹，展开时才读那一层，走 `cachedBrowsable` / `listBrowsable`。点名字跳转并关闭，方向键与回车可用，打字就地过滤。
  可接住拖来的条目（`fileDropTarget`），右键可在新标签页打开与固定到快速访问。
- 钉住：右上角图钉钉住后跳转不关，成为浮在网格左上方的卡片，可拖动与调整大小。右下角留给 `FloatingTasks`。
- 压缩包：作为能展开的节点；要密码时在节点下就地出一行输入框。
- 窄窗口：从面包屑召出，用底部面板形态，不做钉住。
- 实现：普通 `Layout` 加 `Popup`，不用 `SubcomposeLayout`。
