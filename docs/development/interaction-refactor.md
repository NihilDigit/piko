# 交互与状态归属重构

本次重构依据 2026-10-10 的业务审计与交互讨论。目标是让桌面与移动端分别管理交互状态，
共享真实业务状态；页面的显示与关闭不决定业务执行的生命周期。冲突优先在 UX 的统一动作入口阻止，
执行端保留必要的提交检查，不建立覆盖所有业务的通用锁与调度框架。

前一轮实现于 2026-10-11 按主题在本地提交；随后又开始多上下文交互调整，目前是工作区中的后续改动。
先看下方“必须成立的边界”和“当前结构”了解本轮目标，再看 [审查指南](interaction-refactor-review.md)
区分旧提交证据与新增验证。“推进记录”保存各阶段当时的做法，不能覆盖本轮有效规则。

## 必须成立的边界

- 文件仓库拥有文件事实、缓存、索引与变更，不拥有标签、返回栈、页面选择或面板状态。
- 浏览上下文拥有位置、查询、分页、选择与报告筛选；窗口或导航条目持有并释放它。
- 工作区用稳定 ID 持有文件、查重和导入草稿；两端允许多个查重与草稿，同一起点按目录 ID 复用查重。
  移动端保留一个主文件位置，工作在完整页面中呈现，最小化保留并返回来源。手机通过底部 Sheet 选择工作，平板宽窗口用居中对话框；桌面只使用标签。
  草稿和查重只从「正在进行」或桌面标签恢复，不计入任务列表、任务徽标，也不在执行详情中注册继续编辑动作。
- 业务工作流、执行尝试、远端任务、报告和资源会话分别建模，保留各业务的完成及停止语义。
- 添加链接的可编辑内容与解析预览资源属于业务会话；展开、收起、焦点属于呈现层。
- 查重扫描与报告不拥有页面筛选。切换上下文或最小化不停止扫描；明确关闭查重上下文才停止并丢弃该报告。
- 重要结局与待输入请求可以查询；一次性提示不是结果的唯一来源。
- 界面订阅可以停止，持续执行不能依赖页面协程或 WhileSubscribed 的订阅数。
- 当前账号运行期、跨账号历史与持久资源分别管理。同账号 client 重建也要正确释放旧资源。
- 保留已发布任务与清单格式的读取能力；开发期 UI 状态直接修改。

## 当前结构

| 所有者 | 持有内容 | 释放条件 |
| --- | --- | --- |
| 文件仓库 | 文件事实、索引、缓存及变更 | 账号数据切换或进程结束 |
| DriveWorkspace | 桌面文件标签的位置、历史、滚动、高亮与剪贴板 | 账号切换；退出清除临时交互 |
| MobileFileWorkspace | 单页主文件位置、历史、滚动、高亮与剪贴板 | 账号工作区结束；位置按账号缓存 |
| WorkspaceContexts | 两端文件、查重、导入草稿的稳定 ID、顺序与活动项；只有文件位置写入标签缓存 | 关闭对应上下文或账号工作区结束 |
| WorkspaceViewModel | 各 ID 的浏览会话、查重扫描和导入草稿 | 关闭对应上下文或账号 ViewModelStore 清除 |
| SaveTargetBinding | 当前前端主文件位置的保存目录上下文 | 账号工作区结束，按绑定身份释放 |
| 账号 ViewModelStore | WorkspaceViewModel 与工作区恢复记忆 | 退出账号或切换账号 |
| 浏览会话 | 查询、选择、筛选、搜索展开、分区展开及解析投影 | 关闭标签、页面出栈或账号结束 |
| AccountExecutionScopes | 已接受文件操作的执行协程 | 活动账号结束或进程结束 |
| FileWriteSession | 普通写操作、远端复制引用、已确认及待确认结果 | 当前账号运行期；完成结果保留最近 100 项，待确认结果显式移除 |
| HistoryEditSession | 播放/最近添加记录的移除、清空及待确认结果 | 当前账号运行期；页面只提交事件标识并订阅刷新 |
| VaultEntryEditSession | 归档条目的重命名、移除、可信写入核对及具体撤销关联 | 当前账号运行期；已确认结果最近 100 项，待确认结果显式移除 |
| InstantSaveRecords.attempts | 秒传尝试的冻结参数、已保存 ID、未保存/未执行/待确认结果 | 当前账号运行期；完成后同一 ID 转入既有成功历史，或显式移除 |
| ShareSaveSession | 转存提交快照、远端任务引用、完成回执、规范命名及具体撤销关联 | 当前账号运行期；已确认结果最近 100 项，待确认结果显式移除 |
| OfflineSubmitSession | 普通链接、整包和重新提交的在途/未知回执及无任务即时文件回执 | 已知远端任务转交已有列表或整包跟踪；其余结果当前账号运行期保留 |
| 业务会话 | 查重按上下文独立扫描；解压、归档等保留各自的状态与资源 | 查重关闭其上下文；其他业务遵循各自结束规则 |

界面组合的释放只撤掉绑定，不清除工作区 ViewModel。普通新建、改名、移动、复制、恢复、删除和星标已接入文件写服务；
秒传已保留逐文件回执并限定重试，分享转存由独立业务会话保留远端引用与待确认结果。

## MVVM 约定

MVVM 的主要约束是状态归属、单向数据流与生命周期。页面模型接收用户动作、读取业务来源，
生成只读呈现状态；实际文件处理与资源释放委托给业务服务。普通状态持有类可以作为 ViewModel
的组成部分，无需全部继承框架 ViewModel，也无需把 Compose State 一律替换成 StateFlow。

| 状态或动作 | 所有者与寿命 |
| --- | --- |
| 任务执行、远端引用、部分成功、待确认结果 | 业务会话或已有持久任务存储；按业务的结束规则释放 |
| 目录、搜索、选择、任务筛选与报告投影 | 对应的浏览或工作区呈现模型；配置变化保留，所属上下文关闭时释放 |
| 桌面标签、移动主文件位置与完整工作页面 | 各端工作区交互模型；不写入文件仓库；关闭查重上下文明确结束对应扫描 |
| 可见期间的查询刷新 | 页面可见期；停止刷新不取消已提交工作 |
| 焦点、动画、系统选择器及打开本地文件 | 界面或平台作用域；界面结束后不执行晚到的界面回调 |

ViewModel 不因界面缺少订阅而停止持续业务；业务完成也不要求某个 Composable 正在收集提示。
任务页的 TransfersState 由 WorkspaceViewModel 保留，TransfersScreen 接收该状态而不重新创建，
可见期轮询仍由 repeatOnLifecycle 控制。打开本地文件夹的异步回调留在页面作用域。

当前 DriveScreenState 仍包含部分工作流及列表投影，WorkspaceViewModel 仍直接依赖
PikoServices；这些是尚待收口的接缝。移动主文件浏览已独立于桌面标签；两端只共用 FileWorkspace 能力接口，
不共享导航状态。资料页和临时定位页各自持有浏览上下文。
不能将增加 ViewModel 包装视为 MVVM 重构完成。

## 完成验证

1. 从文件、星标、回收站及报告进入或返回，位置、筛选与选择按所属上下文保留，互不覆盖。
2. 每份导入草稿独立保留预览与编辑；打开时固定默认目标，手选目标只改该草稿，临时资源正确清理。
3. 多份查重与导入草稿可并存并各有恢复入口；移动端查重最多一份，切换或收起不重启扫描或解析。
4. 菜单、按钮、快捷键及命令面板执行相同动作规则；冲突原因及解除条件可以解释。
5. 任务入口能够查看执行中的状态、需要处理的输入和完成/失败结果，支持业务真实提供的动作。
6. 停止扫描、停止归档、暂停传输、取消远端任务、停止跟踪与撤销分别验证。
7. 秒传、复制与分批写操作区分已确认成功、未执行与结果不确定，重试不假设原请求未执行。
8. 共享播放/下载缓存、临时借对象、清单可信写入与撤销顺序不被呈现重构破坏。
9. 换号、同账号重连、桌面关窗、Android 后台与重启的行为符合各业务的实际恢复能力。
10. Android 与桌面编译、相关业务 smoke 测试和真实交互验证通过；截图不能代替生命周期验证。
