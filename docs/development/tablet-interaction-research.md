项目级方案见 [共用能力与自适应交互设计规范](adaptive-interaction-spec.md)。本文保留平板研究和提交复审记录。

## 2026-10-16：跨平台适配目标与积压工作复审

本次整理以共同的业务模型、命令和状态规则支撑 Windows 与 Android 上的不同窗口和输入组合。
手机、平板、桌面是验证场景，不作为三套互斥的业务架构。Windows 触屏窗口、Windows 键鼠窗口、
Android 触屏平板和 Android 外接键鼠窗口都应能完成同样的业务；布局与输入适配分别设计。
以下是根据当前代码和本次讨论形成的复审方向，尚未实施或完成设备验证。

### 决策边界

| 维度 | 决定什么 | 不应决定什么 |
| --- | --- | --- |
| 内容关系 | 列表与详情、文件与信息流、导入树与配置是否适合一起展示 | 仅因窗口宽就新增无明确对象的栏 |
| 实际可用空间 | 导航容器、并列或逐页呈现、工具栏收纳、内容密度 | 执行业务、创建或销毁工作身份 |
| 输入能力与当前事件 | 触摸命中区、鼠标选择与右键、键盘焦点与快捷键 | 功能是否存在、使用哪一套账号或工作区状态 |
| 平台能力 | 系统返回、后台执行、权限、文件访问、外部窗口与媒体宿主 | 是否允许多栏、是否支持键鼠 |

空间以应用窗口和内容容器为准，结合宽、高、字号、系统遮挡和输入法；屏幕比例可帮助判断内容安排，
但不能替代最小可用宽高预算。同为横向窗口，低矮手机和宽高充足的平板不能只凭比例采用同一布局。

输入能力不是 `touch/mouse` 二选一。应分别考虑设备可用能力、当前事件来源、用户偏好与辅助技术。
鼠标移动可以更新悬停反馈，不能令整个页面重排；键盘接入不能隐藏触控操作。
文件的焦点项、多选集合和已打开详情对象需要各自明确，鼠标、触摸和键盘共同操作同一份上下文状态。
命令应有统一的对象、可用条件与执行入口，菜单、按钮和快捷键只是不同触发方式。

共用状态模型不意味着所有视图共用一个可变实例：账号拥有业务执行和结果；每个工作上下文拥有路径、
搜索、选择和草稿；窗口拥有当前呈现与活动区域；控件拥有短暂的按压、悬停等状态。
多窗口的具体实现仍需设计，但不能把窗口焦点放入账号级单例。尺寸改变时应继续投影原上下文，
不在 `DriveWorkspace` 与 `MobileFileWorkspace` 之间临时替换实例。

Android TV 可作为后续输入与显示场景；键鼠可操作不代表已完成电视适配。
遥控器方向导航、焦点可达性和远距离阅读需要单独验证，不能直接套用平板验收结论。

## 1. 推荐方向

Piko 应让有足够空间的平板同时展示有关联的内容。优先做文件与右侧信息流、导入文件树与保存配置、任务列表与详情。这些组合能减少来回切页，而且每一栏都有明确对象。继续使用触控可见的操作入口，不把桌面右键菜单、单击选择和窗口管理整套搬到平板。

当前 `FormFactor.Mobile` 同时覆盖手机与平板，又被用来禁止某些并列布局，约束过大。建议分开四个维度：

- **内容关系**决定是否需要并列：列表与详情、内容与辅助工具，或两个独立工作。
- **实际可用空间**决定能否并列：窗口、导航、系统栏、输入法、字体与铰链共同影响各栏容量。
- **输入能力**决定入口与操作反馈：触控、鼠标、键盘、手写笔可同时存在。
- **系统平台**决定生命周期、系统返回、权限、外部窗口及媒体能力；不直接等同单栏或双栏。

建议第一阶段最多同时显示一个主要工作和一个相关辅助栏。暂不提供任意两份导入/查重/文件工作并列，也不新建一个平板专用标签系统。现有「正在进行」继续管理保留的实例；是否并列是工作内部的布局选择，不能改变最小化、关闭和执行寿命。

## 4. 空间决策：先计算各栏能否工作

### 4.1 两层判断

窗口尺寸档位决定导航骨架和优先候选布局；每个工作容器再按自身实际约束判断。使用窗口 dp，不能使用屏幕像素或设备名称。子页面已被 rail、边距占去空间时，不再次按整个窗口宽度选两栏。[Android 的局部约束指导](https://developer.android.com/develop/ui/compose/layouts/adaptive/support-different-display-sizes)明确区分窗口与组件可用空间。

建议预算：

```text
W = 当前工作容器的可用宽度（已扣导航、外框、安全区；不可重复扣减）
H = 当前工作容器的可见高度（扣局部顶栏、底栏及实际遮挡）
允许左右并列 = 两个连续可用区域都满足各自最小宽度，且 H 满足内容最低可操作高度
```

折叠屏不是把铰链宽度从总宽减掉就结束：有物理分隔时，左右区域要分别容纳一栏，按钮、拖动手柄与弹窗不能跨遮挡区域。水平折叠可候选上方媒体、下方控制；要单独定义，不能直接旋转左右两栏。

| 组合 | 初始容量依据 | 准入建议 |
| --- | --- | --- |
| 文件 + 信息流 | 现代码主区 440 + 分隔 24 + 信息流 360 + 末边距 16 = 840 dp；默认栏宽 420 | 净宽至少 840 再检查实际控件；正常高度优先用默认 420。窗口 840 减去 rail 后通常不足，不能只查 expanded |
| 文件属性 | 属性按打开时的对象展示，长路径与来源可滚动 | 优先独立弹窗或临时面板，不作为常驻双栏的准入场景 |
| 导入文件树 + 来源/目标/提交 | 文件树的缩进、复选框、文件名与预览动作最吃横向空间 | 文件树至少 440、配置约 320–360 加 C；文件树取得主要宽度，不按两栏平分 |
| 任务列表 + 执行详情 | 列表保留名称/状态/主要动作，详情展示结果与处置 | 列表约 360–440、详情至少 400 加 C；逐类测长任务名和部分失败结果 |
| 设置类别 + 设置正文 | 左栏是少量类别，右栏是表单正文 | 类别约 240–280、正文约 400 加 C；正文仍限行长，不拉成满宽开关 |

例如净宽 1200 可按 420 dp 信息流 + 40 dp 分隔边距，留下 740 dp 文件区；净宽 900 则只够 360 dp 信息流和 500 dp 文件区。两者都比统一 70/30 更符合当前控件。若窗口为 900、导航与安全区已占 80，净宽只有 820，此时回退。80 只是演算示例，实现要读取实际测量值。

### 4.3 高度、输入法和字号

- 高度低于 480 dp 是现有控件与 Android 指南共同提示的风险区，应阻止自动开启文件+竖向信息流。但这不禁止所有专门设计的左右布局：导入把长表单放左、可滚文件树放右，可以比上下堆叠保留更多行，需独立验收。
- 不用 `windowHeight < 480` 代替实际可见高度。IME 出现后，剩余区域可能很矮；避免高度跳档导致输入框销毁、键盘关闭又重新展开的循环。保持正在输入的配置栏和焦点，其他栏缩到可滚动或暂时隐藏，不重建业务对象。
- 最小高度应由顶栏、固定操作区与最少有用内容推导。例如导入至少露出文件选择标题与若干可操作行，不能只剩提交按钮；若固定头尾吃完空间，改整栏滚动或压缩非必要摘要，不把字体缩小。
- 字体放大时，先允许标签换行、减少次要列，重新测量关键操作和标题。上表 320/360 等值不能直接乘一个字号倍率当作完整方案：触控目标、文本行高与图像需求变化不同。
- 分屏、自由窗口和拖动分栏只改变呈现；不重新解析链接、不清选中、不停止扫描、不把播放器从头播放。窗口缩小后也不要覆盖用户保存的理想面板宽度，下次变宽再按理想值夹取可用范围。

## 5. 各工作流的推荐

### 5.1 文件与右侧信息流：第一优先级

**关系。** 信息流由打开时的目录或所选视频产生，范围固定；它不是文件列表当前选中项的详情，也不是另一个任意工作。平板可让用户浏览文件并保留同批片段，符合媒体浏览的辅助栏关系。

**开启和关闭。** 在文件页保留可见的信息流按钮。空间够则右侧打开，文件区缩窄；不够则进入完整信息流页面，返回回原文件状态。右栏提供明确的收起/展开和关闭语义：建议“收起信息流”暂停呈现并保留队列，“关闭信息流”结束会话；现代码关闭会清队列，不能把原关闭回调当作新收起。第一版若不增加收起能力，则只保留现有关闭与窄屏页面返回规则，文案必须如实。

**定位。** 建议点击“在文件中显示”在左侧打开临时定位视图并高亮文件，右侧留在原片段，先暂停，用户可继续播放；保留明确“返回原目录”。这能看着片段核对文件，不需要强制隐藏整个信息流。临时浏览只占左栏，不改草稿目标；回到原目录恢复原路径/滚动/选择。窄布局沿用完整定位页，返回恢复信息流。定位后的左栏与信息流范围可以不同，栏头应显示“正在播放：来源目录”，避免用户误以为左栏导航重建了队列。

**文件浏览。** 在打开范围内进子目录仍不更换队列。主动离开范围后，第一版可沿用挂起规则，保留继续入口；不能一边宣称范围固定，一边让普通左栏点击偷偷重开队列。未来若需要任意目录浏览时持续播放，应作为明确的“固定此信息流”功能评估。

**播放。** “看完整”仍进入专用播放器，信息流暂停并保留片段位置。返回同一片段、同一左栏位置。调整栏宽、从并列收成全屏、旋转或打开 IME 时，维持唯一媒体宿主，不同时运行新旧两份播放器。不能仅按 Compose 是否还在动画组合中判断谁播放。

**面板尺寸与触控。** 沿用 360 最低、420 默认作为首轮试验。保留宽度拖动，但24 dp分隔带应有更易触达的手柄或宽度菜单（标准/较宽/最大化），读屏能调整，不能只靠悬停光标发现。视频按比例完整展示，不为填满窄竖栏裁掉内容；控件是否放得下按区域高度和字号测量。

**落点。** 改造 `panelFits`、`feedFrame` 与 `FeedNavigationState`，新增栏内定位状态；不要把整个 `Mobile` 改成 `Desktop`。处理 `ClipFeedScreen` 的首次聚焦：用户主动打开可以聚焦，纯尺寸重排不能抢焦点。

### 5.2 文件属性

属性优先使用独立弹窗或临时面板，不因平板空间宽就改成常驻右栏。属性面板固定打开时的对象，关闭不改变文件选择，也不替换正在使用的信息流。属性的具体弹窗形态仍待比较。

沿用 `PropertiesTarget` 打开时固定对象的约定。多选属性显示当前明确选定集合的汇总，避免把最近点击项当作整个选择。

画廊利用宽度增加有效列数。内容辨认使用现有缩略图，点击后进入现有查看器或播放器。

### 5.3 查重虚拟树

继续把报告作为一份完整工作：根范围、扫描完整性、类别和统计在工作级；虚拟树负责目录/组/文件层级。宽窗口让现有虚拟树获得足够空间，真实路径、大小与内容标识等属性继续用临时弹窗。不要另造一个“平板查重卡片数据源”绕开现有虚拟树与写入检查。

当前虚拟树已经承担层级，额外增加目录树会重复导航并消耗宽度。多选操作明确显示所选集合及范围。

返回规则：弹窗/属性→退出多选→搜索→树内上一级→根部最小化工作。删除一个副本后，不能把选中对象换成同位置的另一个文件；空组消失后保持邻近滚动锚点。停止扫描保留部分报告与关闭报告仍是两个动作。

### 5.4 导入文件选择与来源/目标/提交

平板推荐文件树主栏 + 配置辅助栏。主栏显示选择数、分类和文件预览操作，配置栏显示来源、固定目标、保存策略、已选体积和提交。文件树取得大部分空间；提交始终作用于这一份草稿，在按钮附近再次显示目标与选中数。

未解析的空草稿只有输入，没有必要显示两块巨大空栏；可以用限宽单栏输入，解析出集合后再显示双栏。批量链接则是链接列表/批次状态 + 当前链接的文件选择，批次提交与单行提交要区分；不要同时打开批次列表、来源、文件树、目标四列。

更改目标仍使用独立 `FolderPickerDialog`。第一版保留560 dp上限的居中选择过程，让源文件选择留在背后；取消不改目标。不要把普通文件页临时借作目标栏，否则用户浏览与选择目标混在一起。IME 出现时配置栏可以滚动，文件列表保持选择与滚动；选完文件查看预览回来不能归零。

### 5.5 任务列表与详情

这最适合标准列表详情：左侧可筛选的执行列表，右侧显示一个稳定 `detailsKey` 对应的进度、结果、失败范围及可用处置。进度刷新从同一执行记录读取，不复制快照；移除记录后详情关闭或明确显示已移除。不要按行序号选择详情，任务状态变化会重排。

操作入口保持可见，暂停/重试等高频动作可继续在列表；更复杂的部分失败、待确认、撤销和本地文件详情放右侧。进入多选时，不让右侧单任务按钮误作用于整个选择；可切成所选项摘要，或明确保持单项详情并禁用会混淆的操作。

完成任务从“进行中”筛选消失时，若用户正在读其详情，建议保留详情并标明已完成，直到显式返回或选择其他项；不能在完成瞬间闪退详情。草稿/报告的“继续”仍进入其工作页，不把导入编辑器塞进任务详情栏。任务列表位置、类别与选择在回来后保留。

### 5.6 设置、分享与库导航

设置适合类别列表 + 当前设置正文；在中等但净空间不足时只保留正文及返回。选中类别在左侧高亮，打开WebDAV等下一级仍是设置层级，不重复压一个完整“我的”页。移动端现有 NavDisplay 与新栏内导航需要明确交接，不能把已导入却未使用的 ListDetailSceneStrategy 当作完成实现。

“我的分享”适合分享列表 + 某个分享的链接/有效期/文件详情与管理操作；新建分享的短输入保留对话框。库（星标、历史、最近、回收站）是浏览范围，可使用 rail/drawer 切换范围并保留各自会话，而不是第二个属性栏。回收站危险动作仍清楚表达范围，不能因为出现第二栏而弱化确认。

导航本身可以从底栏变rail，空间非常宽时再考虑带文字的导航。不能同时常驻全导航、库树、文件树、详情与信息流。选取一个服务于当前任务的辅助区，比把每个桌面区域都显示出来更重要。

### 5.7 正在进行与多工作实例

正在进行继续是一份按 context ID 列出的工作切换器。平板适合从顶栏弹出有标题、来源/目标、状态与直接关闭按钮的紧凑选择器，或现有短侧面板；开关不应永久占去一栏。选择工作后关闭选择器，进入该工作布局。最小化返回打开它的来源，关闭只移除指定实例，关闭非当前项不切走当前工作。

暂不支持两个任意工作并列。原因是当前移动端只持有一个主文件浏览工作，两个上下文还需要两份可见导航、活动焦点、返回历史、标题/关闭作用域与操作目标。屏幕够宽只能满足几何条件，不能自动定义这些语义。文件+信息流、查重树+详情、导入树+配置都不是两个独立工作，应优先做好。

后续若反复出现“对照两个目录移动文件”或“从报告拖到另一个目标目录”的需求，可专门设计双文件浏览工作区；先定义源/目标和剪贴板语义，再决定是否扩展成任意双工作。系统分屏/多窗口是另一条能力，需要独立账号、媒体和窗口所有权设计，不在这轮自动承诺。

## 6. 状态、返回、焦点与资源规则

| 状态 | 所有者与保留要求 | 尺寸变化不得做的事 |
| --- | --- | --- |
| 工作身份、草稿、查重执行 | 现有账号工作区与业务会话 | 因少一栏而关闭/重新创建工作 |
| 路径、搜索、选择、目录滚动 | 具体浏览会话；各栏有各自投影 | 把两栏绑定到同一活动路径并互相覆盖 |
| 任务详情/属性对象 | 执行 ID 或文件 ID + 账号；属性保留固定目标约定 | 按列表位置重新认对象 |
| 可见栏、栏宽、活动栏 | 窗口级呈现状态；宽度偏好与临时夹取值分开 | 改变用户原来选的工作/媒体范围 |
| 媒体队列、位置、暂停意图 | 媒体会话 | 转场同时双播、仅因重组从头播放 |
| 输入法与键盘焦点 | 当前输入控件/活动栏；重排后恢复其逻辑身份 | 新挂载辅助栏强制抢焦点或重复弹键盘 |

系统返回按当前可见、可交互的局部状态处理，再退栏内层级，最后退页面。宽布局不能让隐藏栏的 BackHandler 抢返回；缩到单栏后应显示当前用户正在操作的栏。导入主文件树与配置属于一个工作，不应用“返回”无意丢掉草稿；窄屏可通过可见切换动作访问另一部分。

键盘命令以活动栏为范围。Ctrl+A、Delete、方向键作用于焦点所在文件/任务列表；文本框中的全选仍选文字。提供可见焦点框、按逻辑顺序遍历，并用独立区域名称让读屏知道进入“文件”“信息流”“任务详情”。移除详情对象后焦点回到触发项或邻近可用项，不落入已隐藏区域。

触控始终有条目更多、显式多选、主要操作与返回入口。拖放是加速手段，复制/移动按钮与目标选择器仍可完成同样工作。输入设备临时接入/断开只增减快捷能力，不能让页面突然换成不同业务模型或藏起原按钮。

后台扫描和已接受保存不因辅助栏隐藏而停止；媒体不可见时按既有播放规则暂停。网络查询、预览租约、原生播放器和监听器应按对象与可见性管理，不能在每次宽度变化时创建一套。缓存继续按账号隔离。

## 7. 不应并列的例子

- 改名、删除确认、输入压缩包密码：短且要求明确完成，不值得常驻一个工作栏。
- 选择移动目标 + 可自由变化的原文件选择：会混淆本次源集合；源应先固定。
- 导入全编辑器 + 任务全编辑器：对象和提交范围不同，且双方都有底部主按钮。
- 大字号或开键盘后只剩标题与固定提交栏的双栏：宽度合格也不可用。
- 没有选择对象时自动常驻属性/详情，以及列表页强塞三个空区域：空间利用不能靠空白面板证明。
- 把模态侧面板当作非模态辅助栏：视觉相邻却挡住主区，用户仍不能同时工作。

## 8. 渐进实施与验证

### 第一阶段：空间能力和信息流

先把 `twoPane/desktop` 的用途拆清：保留平台/输入约定，单独计算“此内容可显示辅助栏”。沿用现有净宽预算，加高度/字体/铰链检查，接入平板信息流。定义右栏定位、完整播放、窄回退和唯一播放器宿主；同时补触控宽度调节。此阶段不顺带重做桌面标签。

### 第二阶段：单个工作内部多栏

导入树+配置与任务列表+详情先做，收益直接，业务对象已明确。查重继续优化虚拟树与真实文件操作，属性保持临时呈现。每加一组双栏都要先通过布局来回切换的状态验证，避免批量铺开后无法定位归属问题。

### 第三阶段：导航

研究设置类别/正文与分享详情。属性继续按独立弹窗或临时面板比较；不默认三栏，不引入任意双工作。只有实用反馈证明必要，再评估双文件浏览及系统多窗口。

### 可测场景

这些是未来验收计划，本轮均未运行。

| 维度 | 必测变化 | 验收重点 |
| --- | --- | --- |
| 宽度边界 | 599/600、839/840，以及扣rail后的实际准入值前后1 dp；1280→800→600→1280 | 不是只在整机尺寸过线时正确；无对象/选择丢失 |
| 高度 | 860×400、1280×480、1280×800；实际正文高度与窗口高度分别记录 | 控件和至少可操作内容存在，媒体不裁切，主按钮可达 |
| 字号与显示缩放 | 系统默认、大字号、最大支持字号；长中文/英文名 | 不靠缩小字号保双栏；关键目标路径和关闭按钮可辨认 |
| IME | 导入输入中展开/收起键盘，随后拖分屏边界 | 输入不丢、焦点不跳、不会重复开关键盘 |
| 折叠 | 内外屏、垂直分隔、水平半折、遮挡与不遮挡铰链 | 栏分别落在可用区，按钮不跨铰链 |
| 信息流 | 打开→调宽→定位左栏→回原目录→看完整→返回→缩窄→变宽→关闭 | 同一队列和片段；不双播、不重新取范围、不误改文件位置 |
| 属性 | 多选后看属性；信息流开着查看属性；属性对象被删除 | 作用对象固定，关闭弹窗后回到原工作 |
| 导入 | 两份草稿、不同目标、滚树、预览、IME、横竖切换、返回提交 | 当前草稿身份与选择不串，目标选择取消无副作用 |
| 查重 | 扫描中变窄、停扫保结果、多选、删副本、切类别再恢复 | 虚拟树完整性与局部返回正确，操作作用于明确文件 |
| 任务 | 读详情时完成/失败/排序变化/筛选变更/移除/恢复草稿 | 详情追随ID与最新状态，不读旧快照，不跳错项 |
| 输入 | 纯触控完成全流程；接入/断开鼠标键盘；Tab与快捷键 | 操作都可见，快捷键作用于活动栏，悬停不是必要条件 |
| 生命周期 | 分屏切应用、Activity重建、切账号、播放器后台/前台 | 无资源泄漏/跨账号状态；会话内与跨进程承诺分清 |

## 9. 已确定方向与待研究事项
