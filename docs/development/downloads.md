# 播放与下载缓存

添加链接面板中的分享文件与已收录的解析条目可直接下载；解析行的关联文件合并为一个批次。
没有内容哈希的条目不进入直接下载队列。下载使用 GCID 和大小识别内容，不把分享者的文件 ID 当作当前账号的 ID。
任务记录 `leasedSource`，由 SDK 临时借出文件对象获取直链并清理；借出位置使用面板当前选择的云端目录，
独立于面板预览目录。关闭面板不取消下载，暂停和重启后仍凭持久来源续传。
相同内容的重复请求复用任务，未完成任务播放也使用同一稀疏缓存。

原画播放、按偏移读取和整文件下载通过 `PikoFileCachePool` 使用同一份 SDK 文件缓存。
缓存按账号、GCID、文件大小和流表示识别；转码片段继续使用可淘汰的 `FileClipCache`，不与原画混用。

每个使用者持有单独的引用。下载任务另有持久化保留标记：暂停保留数据，完成交付或取消才释放标记。
多个任务使用相同内容时，释放其中一个不影响其他任务。最后一个引用释放后，缓存与句柄关闭；
没有下载任务保留的数据一并清理。启动清理保留任务记录中的缓存及正在使用的文件，只删除本应用命名的暂存文件。

## 稀疏存储与恢复

`SparseFileStore` 在真实偏移上写入 256 KiB 块，文件创建时请求稀疏属性，不预分配整文件。
文件长度不表示下载进度：头部与尾部先到时，中间仍可能有空洞。有效块记录保存在 `.blocks` 文件，
包含格式、内容标识、长度、块大小和 CRC 校验。

写完的块立即可供读取；数据文件同步成功后才发布位图。同步周期为两秒，完成交付前也会同步。
位图损坏、内容标识不符或数据文件截短时，相应块重新下载。旧版顺序下载的完整块可导入，
未写满的最后一块重新请求。

下载先取头部 2 MiB 与尾部 512 KiB，再补中间。范围按连接设置分窗提交；蜗牛模式在请求发出前等待额度，
播放读取仍保持前台优先级。所有任务的进度与速度每半秒统一采样，共享缓存的网络字节只统计一次。

普通目录的完整文件通过临时文件交付。Android SAF 先使用私有暂存文件，完成后复制到目标文档；
有效块存储使用普通文件系统路径。未完成媒体可从传输菜单播放，读取下载元数据与缓存，缺块再向云端请求。

## 批次调度

单文件、多选文件和所有文件夹共用三个运行位置，各组轮流获得空位。取消中的任务完成收尾后才腾出位置。
整批暂停先暂停排队项，再取消运行项；暂停全部覆盖排队任务，防止完成回调补开下一项。

文件夹列举共用四个请求位置，并记录已访问目录。各文件一次加入任务表，路径保持目录结构，
清理名称后冲突的条目加序号。重复操作复用已有任务，账号间任务标识分开。
SAF 按父目录批量枚举已有文件，避免每个文件重复遍历整条路径。
