# 自适应前端框架（2026-10-17）

这版实现把文件、独立导入草稿和查重报告放进同一账号工作集合。布局变化只改变展示方式；工作身份、业务执行和账号资源边界沿用已有重构。

## 状态与布局

- `WorkspaceViewModel` 使用固定的 `workspace` key，账号级 `AccountPresentationStores` 持有它。所有平台共享 `DriveWorkspace`，文件浏览会话固定绑定标签 ID；窗口尺寸和输入方式不参与 owner 创建。
- 文件、草稿和查重使用 `WorkspaceContexts` 的同一有序集合。关闭草稿释放编辑，已提交执行继续由业务作用域结算。关闭查重才释放扫描与报告。
- 常驻标签栏要求窗口至少 840×480dp。信息流根据实际内容区容量决定并列，导入根据自身净宽高决定左右布局。低高度宽窗口仍使用紧凑布局。
- 窄窗口的入口为 24dp 圆角描边方框内的标签数，打开全页两列页面缩略图总览，标题与关闭按钮位于卡片顶部；宽窗口恢复当前工作并显示标签栏。`WorkspacePageSnapshot` 从已经绘制的页面捕获实际画面，最长边 512px，读回间隔 350ms；`WorkspaceSnapshots` 在账号 owner 内保留最多约 8MiB 的像素缓存。总览打开时暂停捕获，直接读取缓存，不组合后台业务页面或触发解析、扫描、预览。关闭标签和释放账号清理对应快照，尚未捕获或已被缓存淘汰的页面显示明确空态。
- 总览卡片采用深一档的圆角底壳，固定 48dp 标题栏；内嵌浅色圆角预览区，四周保留 8dp 底壳，统一 3:4 比例。标题只占一行，关闭按钮位置保留，卡片高度不随标签类型变化。
- 新文件标签、查重或导入草稿创建时，窄窗口的数字入口更新数量，旧数字向上滚出，新数字从下方滚入；字重、外框和颜色不变。事件由工作区持有，跨页面呈现仍能看到；恢复旧标签、切换和关闭不触发。减少动画时直接更新数字。
- 草稿和查重的窄窗口路由仍保留来源页。草稿在播放器前台完成时，只清理失效的工作路由，播放器保持在栈上。
- 触摸长按进入多选，鼠标保留副键菜单和修饰键选择；输入切换不清除多选。宽窗口每行仍有可触摸的更多操作入口。标签快捷键在主壳接收，避免退出总览后因焦点不在工作内容内而失效。

## 能力与呈现（2026-10-17 补充）

操作可用性取决于对象、业务上下文和平台提供的能力，窗口尺寸只决定入口如何排列。条目面板与右键菜单共用完整操作集合；面板超出一屏时滚动，不以固定行数删除操作。

这次检查补齐了窄窗口的文件夹查重、子树规范命名、在新标签页打开、固定快速访问、剪切与复制、库中复制到、来源链接复制与打开。粘贴在窄窗口列表页眉菜单中提供。快速访问可从路径面板的固定列表和命令面板进入。目录图在宽窗口使用原浮动面板，窄窗口用临时面板承载同一棵树；路径输入和前进也有窄窗口菜单入口，相关键盘快捷键不依赖布局。播放器音量入口由宿主的音量能力决定。

保留的条件包括回收站、压缩包、归档记录、上传中对象和非工作区浏览上下文的业务约束，以及外部播放器、上传源、旋转等宿主能力。任务详情并排或整页、属性浮卡或 Sheet、标签栏或总览、设置目录并排或单列属于呈现变化；下拉刷新与副键菜单属于输入差异。

## 路由和标签操作

顶层 `MainTab` 切换文件、任务和我的；`Screen` 栈记录资料页、临时浏览、设置、播放器及窄窗口的 `Workspace(id)`；账号工作区 `WorkspaceContexts` 保存文件、查重、导入的稳定身份和活动项。宽窗口将同一工作嵌在标签栏下，窄窗口以完整页承载。任务详情是任务页内部的列表/详情状态，不创建工作标签。

标签入口与 Ctrl+T、Ctrl+W、Ctrl+Tab 只在文件工作区及其浏览、查重、导入页生效。任务页和设置、播放器不操作背后的标签。从任务页创建导入草稿时打开对应工作页，返回仍可回到任务来源。

普通新建标签（按钮、菜单和 Ctrl+T）从网盘根目录开始；文件夹的「在新标签页打开」继续使用指定目录。窄窗口总览固定显示标签总数，并直接提供新建和关闭其他标签；宽窗口在标签栏操作菜单提供关闭其他标签。批量关闭始终先确认，保留发起操作时的当前标签；有未提交草稿、扫描或查重结果时说明关闭影响，取消时不关闭任何标签，已提交执行继续结算。只剩查重或导入标签时不强留一个可见文件标签；返回文件浏览或关闭最后一个辅助工作时恢复文件入口，底层账号资源和接收目标仍保持可用。

宽窗口标签可用鼠标或触摸水平拖动排序，靠近标签栏边缘时自动滚动。排序更新同一工作集合，窄窗口总览沿用该顺序；工作身份、活动项、浏览状态和草稿会话保持，文件标签顺序沿用原格式存盘。Ctrl+Shift+PageUp/PageDown 可移动当前标签，任务页不响应这些工作区快捷键。

## 导入接缝

磁力解析完成后，主区复用 `DriveFileGrid` 的列表/海报和 `DrivePathTitle` 的地址栏、路径输入及目录菜单。投影浏览子树禁用真实文件拖放注册。输入是 `InstantSheetState.projectedSaveFiles`，展示按当前选择、字幕规则与规范命名得到的最终路径；这些 `FileStat` 只用于浏览，不向仓库登记虚拟文件，也不自动预览。

来源区由完整解析路径构建 `ImportTree`，保留原名、任意嵌套及 CJK 文件名。`LazyColumn` 虚拟化全部来源行，目录选择按真实后代计算半选；搜索覆盖完整解析树，过滤不改变保存选择。来源选择可单独勾选字幕和广告，并覆盖配套字幕默认偏好。结果与来源页的搜索、展开、导航和滚动分别保留，布局往返仍使用同一份保存状态。

`WorkspaceTreeRow` 是目录悬浮面板与导入树的共同层级行。导入来源树额外提供保存选择框，预览与下载放在结果区；目录面板保持导航能力及原来的拖动、停靠、钉住和自动收起时序。导航树仍是懒加载，搜索范围仍为已经加载的目录；导入树搜索覆盖已解析的全部原始路径，清单不完整时明确提示。

默认开启规范命名。普通保存沿用既有秒传/整包离线路由。引用保存通过同一目录准备与回执流程，直接向绑定原 client 的 `VaultStore` 可信写入 GCID 引用，不秒传内容；缺少 GCID 的选择不能提交引用保存。预览仍由原租约预算和临时对象会话执行，只有用户主动点击才发起。

保存回执保留成功、失败、未执行和未知部分。任务页的重新查询仅查目录和实际内容，唯一匹配才确认；缺失、歧义仍保留未知，重查不再次提交写请求。已核对完成的记录进入已完成分组。

多链接的原始树和最终保存结果分别平铺在同一工作区，单视频直接成行，保留来源内部层级、独立身份与勾选状态。保存位置、命名和引用保存共用，执行继续由各链接的状态机分别结算。

**尚未接入的范围**：分享链接继续使用现有分享浏览与转存组件，只支持当前层选择。`ShareSaveCommand` 每次携带一条 ancestors 路径，跨层选择还需要一个拥有目录准备、多路径提交和聚合回执的执行会话。

## 任务与信息流

任务页以铺满内容区的列表为主，按需要处理、进行中、已完成组织，保留类型筛选；已提交归档、解压、上传和文件处理不占工作标签。详情采用网盘属性的承载方式：宽窗口可拖动的 FloatingPanel，窄窗口 PikoSheet。打开详情保留列表宽度与批量勾选，关闭详情仅结束查看。停止、暂停、取消、移除记录、撤销仍由各任务的真实能力提供。

宽窗口按列对齐名称、状态与进度、容量、速度和目标位置；根据实际列表宽度逐步增加可见字段。进度和尾部操作区固定宽度，避免操作数量影响对齐。窄窗口将同一份任务投影上下排列。多选框默认隐藏，鼠标悬停时在该行的固定前导位置替换图标，移开后恢复；触屏长按进入多选。进入多选后所有行显示勾选框，退出后恢复普通状态。批量选择期间固定已显示任务的分组与顺序，进度和状态继续更新，退出选择后恢复实时排序。

蜗牛模式继续复用 `SnailModeToggle` 和上限设置对话框，位于速度旁；切换开关保持已设置的上下行限制，开启时显示限速并强调任务入口。

信息流容量足够时与文件并列，Android 平板也适用；支持主动全屏。定位文件暂停播放并保留右栏，在文件区定位，保留返回来源。窗口形态转换继续共享 `ClipFeedSession` 的队列与取流资源，每次只让当前展示位置播放。原生解码器在布局切换时的实际续播手感仍需设备验证。

## 组件组合

对象持有状态、行为和可替换能力，Composable 负责渲染，通过显式参数与插槽组合。动作沿用 SheetAction，任务进度沿用 WorkProgress，树行沿用 WorkspaceTreeRow。

优先整理详情：统一宿主负责打开、定位、拖动、滚动约束、关闭及宽窄呈现；文件和任务分别提供自己的状态投影与内容组合。标题、属性表、进度、回执与动作区分别复用。批量选择、当前查看对象、面板几何状态分开持有；面板关闭仅结束 UI 订阅，业务执行沿用现有账号会话。

网盘属性与任务详情共同使用 components/DetailHost：DetailPanelState 持有查看对象和浮窗几何状态，DetailPanelStore 按所属导航或任务状态保留实例，跨宽窄布局重建后继续查看。FloatingPanel 和 ItemPanelAnchors 位于 components 包。DetailHeading、DetailFields、DetailActions 作为内容组合；ItemDetailsContent 显式提供内容，ItemDetailsSheet 负责独立 Sheet 承载，移除了隐式判断嵌入容器的 LocalEmbeddedItemDetails。

其他组件族包括：列表行与批量选择组合、树的层级/展开/选择/动作组合、同一动作描述在工具栏/菜单/面板中的不同呈现。布局策略只决定排列与容器，能力由对象与业务条件决定，输入适配负责手势与键盘。原型和 shots 复用生产组件，只替换假数据或状态提供者。

输入来源可在同一窗口内随时改变。任务行的长按处理器保持注册，在触发时读取当前输入来源；避免第一个触摸事件使回调从空变为非空，重置正在进行的长按手势。悬停勾选与触摸长按的回归包含鼠标转触屏的首个操作。

来源：Compose state-hoisting 中的 plain state holder 职责划分，以及 architecture 中状态向下、事件向上的单向数据流。verify-shared-details-tasks 覆盖两类详情、跨宽窄切换、列表宽度、选择保留、进度对齐和蜗牛模式。

## 条目构件与链接解析：重做依据（2026-10-17 研究方案）

本节记录当前工作区代码与原始规范的核对结果及构件边界。首批文件呈现构件、来源能力绑定和裁剪完整性保护已接入；完整清单获取、结果网格适配器等后续范围仍按下述方案推进。

### 统一什么

网盘、解析来源、保存结果和分享内容使用同一套文件呈现构件。文件的来源决定数据适配和真实能力，布局决定构件位置与信息密度，输入决定激活、选择和动作的呈现方式。业务会话继续持有解析、保存、预览租约和执行结果。

同一集视频可以在列表中横排、在海报墙中纵排、在来源树中带层级缩进、在详情中展示完整属性。图像、名称、标记、状态和动作保持相同语义与视觉规则，分别采用合适的尺寸和排版。文字、图标和触控目标按项目 token 取值，不对整个组件等比缩放。

MD lists 的 leading/content/trailing slots 支持这种组合；cards 的 Adaptive design 明确允许同一内容在横排、纵排、卡片和列表之间重排，并保持控件与能力。自定义槽位的交互目标至少 48×48dp，选择语义与嵌套动作须单独校验。

### 共用构件

| 构件 | 统一职责 | 已有基础与需要收敛的地方 |
| --- | --- | --- |
| 图像与占位 | 缩略图、海报、文件夹、类型图标、防窥、加载与失败占位 | `FileVisuals`、`SpoilerThumbnail`、`PosterCard`；大小和图像比例由布局提供，呈现本身不创建临时文件 |
| 名称 | 显示名、原名、完整名称、计划保存名称、扩展名策略 | `DriveItemName`、`ItemNames`、`DetailHeading`；源名称和计划名称分开保存，改显示名不改变条目身份 |
| 元信息与标记 | 大小、数量、日期、画质、字幕、归档、未收录、结果状态 | `MetaRow`、`MediaTagRow`、`itemMarks`、`WorkProgress`；各布局选择字段与优先级，文案和格式规则共用 |
| 表面与状态 | 圆角、色阶、悬停、按下、焦点、选中、活动项、定位提示 | 沿用 M3 色彩角色与项目 Frame；焦点、选中、定位和正在查看是不同状态 |
| 选择与纳入 | 批量选择、部分选中、纳入本次保存及其无障碍语义 | 一套控件，多种显式用途；批量选择和保存清单使用独立控制器 |
| 动作 | 主操作、快捷动作、完整菜单、属性、暂不可用原因 | 复用 `SheetAction`、`ActionAvailability` 与 `layoutActions`；同一动作描述驱动图标、菜单、Sheet 与快捷键 |

列表行、海报块、树行、详情是这些构件的布局组合。树的层级、展开、懒加载和可见子树属于树容器；列数、排序、框选和滚动属于集合容器。任务保留自己的工作模型，复用其中的图像、名称、状态和动作构件。

首批实现位于 `components/FilePresentation.kt` 与 `FileArtwork.kt`：网盘与解析文件分别适配 `FilePresentation`，共用图像分类、防窥、名称、信息、星标/归档标记、选择控件和实际动作描述。海报的文件夹绘制已迁入共用图像组件。网盘列表与海报的鼠标悬停勾选、触屏首次长按复用输入规则；来源树继续使用独立的保存纳入状态。MIME 类型补充分类保留，图像组件不取得播放租约或创建远端文件。

树的展开控件位于勾选框之前。纯文件列表不保留箭头列；有分支的树保留统一箭头列和每级缩进，避免叶子图像向父目录左侧倒退。勾选框与文件图像之间不再夹一个没有箭头的空槽。

### 数据与能力边界

每种来源由适配器生成统一的文件呈现模型，至少包括稳定来源引用、条目实例 key、名称、图像描述、元信息、标记和状态。真实网盘 ID 只存在于确有远端对象的引用中；解析文件以草稿、来源与原始路径标识，保存结果以计划内的稳定身份标识。GCID 相同也可能是两个不同位置或两个不同来源项，不能据 GCID 合并 UI 身份。

能力由来源适配器与现有命令层提供。没有能力的动作不注册；暂不可用的能力保留原因，执行时再次核对账号、对象和目标状态。展示层不根据一个伪造的网盘 ID 推断可改名、可拖放或可删除，也不靠空回调掩盖不存在的能力。

| 场景 | 共用呈现 | 操作与选择的含义 |
| --- | --- | --- |
| 网盘列表、海报墙、图库 | 相同文件呈现与动作，只换布局 | 浏览与文件管理，批量选择作用于真实命令目标 |
| 解析来源树 | 原始名称、层级、大小、可用性标记 | 勾选决定最终保存内容，目录按真实后代计算半选；来源信息提供复制、重试和移除链接 |
| 保存结果区 | 计划中的最终名称与目录，复用普通网盘浏览布局 | 路径导航、搜索、列表/海报、预览、下载和共用属性；后续若提供改名，命令应修改保存计划 |
| PikPak 分享 | 相同文件构件与树容器 | 可转存、可访问子目录等能力按分享后端提供；当前不能宣称支持跨层选择 |
| 目录悬浮面板 | 相同名称、文件夹图像和树层级构件 | 导航、展开与当前目录，不提供来源选择框、预览和下载 |

普通批量选择沿用鼠标悬停勾选、触屏长按进入，进入选择后统一显示。解析页“纳入保存”的勾选是编辑保存清单的主要控件，应保持可发现；它不跟随普通批量选择模式收起。箭头只改变展开，独立子动作只执行自身动作；同一项不重复暴露两个复选入口。

鼠标与触摸使用同一份能力与选择状态。需要保留不同场景的主操作语义：网盘的打开、来源树的展开/纳入、保存结果的路径导航由各自交互绑定明确提供。布局变化不改主操作，不因窄屏移除能力。鼠标/触摸切换时长按回调保持注册，在触发时读取输入来源。

### 当前重复与不合理依赖

- `FileListItem`、`PosterCard`、`WorkspaceTreeRow` 已共享首批构件与输入规则，外层保持各自布局模板。图库仍通过原适配入口使用部分构件，后续继续收敛。
- `ImportResultProjection` 将保存计划适配为 `DriveFileGrid` 的只读条目，使用 `import-file:`/`import-dir:` 命名空间，以链接身份和原始条目索引隔离同名文件。预览、下载映射回真实来源；属性复用 `DetailHost`、`PropertiesPane`，不会把投影 ID 传入网盘写操作。改名与发起多选为可选回调；网格的完整数据接口仍依赖 `FileStat`，后续继续收敛。
- `DriveCell` 为每个文件注册属性、改名、中键、拖放等行为；这些注册也应由绑定中的能力决定。可以保留网盘特有的命令适配，不把命令执行搬进基础构件。
- `ResolvedImportWorkspace` 主内容始终显示计划保存后的虚拟网盘。宽窗口右侧管理面板包含原始文件树和保存设置；窄窗口复用 `TaskSheetScaffold` 的 standard bottom sheet，无模态遮罩，收起后仍能操作结果浏览区。标题右侧提供搜索与保存设置按钮，搜索按需展开；移除中点串联的摘要和额外收起箭头，Sheet 通过拖动条、拖动与返回收起。保存动作固定在管理面板内容底部，两种布局一致。设置与树共用滚动区域，低高度也可访问；状态按优先级合成一条。当前 Sheet 使用收起/展开两档，中间停驻档仍待补充。
- 单链接和多链接使用同一工作区。多条链接的原始树直接接成一份 forest，单视频直接成行，保留各来源内部的目录层级，不添加按链接分组的外壳。搜索、设置与保存动作共用；相同路径不跨来源合并，勾选保留来源归属。左侧汇总各保存计划，重复名称仍为独立条目。来源信息中的移除只影响对应链接；批量执行继续逐链接记录结果，成功项移出、失败项保留。以引用保存对全部来源生效，缺少 GCID 的所选文件会阻止提交。
- `ImportWorkspaceViewState` 由 `WorkspaceViewModel` 按导入上下文持有，组合管理、浏览与属性状态；切换标签与窄窗口路由继续使用同一实例，关闭上下文时释放。宽窄布局由实际可用尺寸决定，低高度且有足够横向空间时并列；Sheet 与侧栏的替换在组合阶段进行，避免在子组合的测量过程中销毁弹层。

### 解析链路的实际边界

当前链路为 `extractLinks → InstantSheetState → InstantMagnetRepository → SDK resolveMagnet → 原始文件清单 → 文件识别与默认选择 → 保存投影 → 保存计划/执行`。

| 输入 | 当前取得清单的方式 | 当前限制 |
| --- | --- | --- |
| v1 磁力、40 位十六进制/32 位 Base32 hash | 归一化后请求 `/drive/v1/resource/list`，不创建离线任务；保留原始相对路径、大小与可选 GCID | SDK 请求顶层 500 项并标记 `truncated`，尚未跟随分页；应用已提示部分结果，限制自动裁剪 |
| 本地 `.torrent` | `TorrentMagnet` 提取原始 info 字节求 SHA-1，取名称，转换磁力后走同一服务端索引 | 未保留本地已有的文件清单；未区分 v2；有本地元数据却仍可能因服务端未收录而无法浏览 |
| PikPak 分享 | `ShareSaveState` 经分享接口逐层加载 | 当前层选择，进目录清空；混合输入中优先识别首个分享，未统一成可混合的批量来源 |
| HTTP(S)、ed2k、thunder | 能从粘贴文本提取，当前主要交给云端离线提交 | 应用尚未提供同等的保存前完整清单；不能仅因识别到 URL 就显示一棵完整目录树 |

文件名识别和目录编排应作为原始目录之上的解释与保存计划，保留原始路径。字幕、广告、版本与默认选择都是可以检查和覆盖的建议。来源搜索不能改变勾选；筛选掉的内容仍存在于完整来源中。分享的懒加载范围与磁力完整清单的搜索范围要区分。

解析结果应分别报告：目录是否完整、元数据是否可用、GCID 是否已知、取流是否实际验证。当前 SDK 将所有 GCID 都为空的结果返回 `null`，正常未命中占位与“有目录但没有 GCID”不能由上层区分；有 GCID 也不等于已经验证内容可读。界面应能呈现“有目录、缺引用”“只有部分目录”“需要提取码”“请求失败”等不同状态。

本地 `.torrent` 可先提供文件名、路径与大小，再由索引补充 GCID。磁力本身提供的是内容身份，取得目录仍依赖外部元数据。v1、v2 和 hybrid 需要显式识别；纯 v2 不应无条件对 info 求 SHA-1 并包装成 v1 `btih`。本机服务端目前对 v2 的实际支持尚未探测。

**清单完整性保护已接入。** 部分清单中已知 GCID 的选择可以单独秒传或保存引用，整包裁剪计划不可执行；批量保存也阻止绕过。`packSave` 在提交前再次检查。实际删除前重新查询原来源，要求清单完整且保留路径都存在，再调用 SDK 裁剪；这个检查同样覆盖已持久化的旧任务，未改变其数据格式。校验失败保留产出，并以清理失败及具体原因结束，清单完整后可仅重试清理。现有 Fake 服务回归覆盖未列出文件保留、路径不匹配、旧任务恢复和完整后重试，未对真实账号执行裁剪。

### 保存引用与归档重解析

保存引用已直接按目录写入 `VaultStore` 清单，内容文件不经 `instantCreate`；目录准备和清单上传仍是实际写入。普通保存、引用保存、预览临时对象和下载是独立能力，不因共用图像构件而相互触发。

归档来源重解析可以复用同一个解析结果模型，作为批量取得候选 GCID 的快路。按来源身份、原始路径、大小与已有可信 hash/清单校验匹配；证据不足的节点保留现有查询路径。先确认引用清单写入，再按现有归档事务决定源文件处理。只凭名字或大小不能确认内容相同，解析不完整时不进入自动替换/删除流程。

### 实施顺序与验收

1. 将清单完整性、元数据和 GCID 可用性拆开，补齐分页、全部 GCID 缺失、本地 torrent、混合来源的契约。先限制不完整清单的裁剪。
2. 提取统一呈现模型与来源适配器，从 `FileVisuals`、`DriveItemName`、`MetaRow`、`SheetAction` 等现有构件收敛，迁移网盘列表和海报两种布局。命令与业务状态仍由原 owner 持有。
3. 解析来源树、保存结果和分享内容接入相同构件，移除伪造 `FileStat` 与空操作回调。保留目录原貌、独立搜索/展开/选择，以及当前真实能力边界。
4. 用这套构件重做宽屏结果/管理并列、窄屏结果/管理 Sheet，再推广到目录面板及任务中引用的文件呈现。

同一组数据至少覆盖：宽窄与低高度切换、列表/海报切换、鼠标/触摸交替、悬停勾选、首次触摸长按、键盘与右键、CJK 长名称、深层合集、同内容不同来源、字体放大、图像失败与防窥、缺少 GCID、部分清单、分享跨层、普通保存与引用保存。需要核对主操作和子动作互不误触、选择语义与状态保留、视图切换不创建预览对象或重发写请求。深树要保留可读名称宽度与路径上下文，不通过持续缩小字号解决层级空间。

研究来源：本仓库 `MagnetLinkText`、`TorrentMagnet`、`InstantSheetState`、`ImportWorkspace`、`DriveFileGrid`、`FileListItem`、`PosterCard`、`WorkspaceTreeRow`；相邻 SDK 的 `MagnetResolveEndpoint`、`OfflinePruneEndpoint` 及其现有测试。MD 依据为 docmirror4a 的 `m3-material-mirror/pages/components/lists.md`、`cards.md`、`styles/color/roles.md`，以及 Android Compose `state-hoisting.md`。协议依据：[BEP 3](https://www.bittorrent.org/beps/bep_0003.html)、[BEP 9](https://www.bittorrent.org/beps/bep_0009.html)、[BEP 52](https://www.bittorrent.org/beps/bep_0052.html)。后端裁剪与保存验证使用假服务端，未执行真实账号的删除探测。
