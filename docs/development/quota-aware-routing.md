# 配额感知的离线提速与归档取流路由设计

本文档记录后续版本拟推进的传输配额优化与整包离线提速方案。核心目标是在**不向用户界面暴露「秒传」与「离线」底层通道差异、不改变 `pikpak-kotlin` SDK 面向纯流媒体客户端（如 Animeko）默认行为**的前提下，大幅压缩整包离线体感延迟，消除归档点播与大体积单文件保存对月度上传流量配额的消耗。

---

## 一、背景与协议约束

1. **配额结构不对称**：
   - 标准会员月度上传流量配额为 `1 TiB`，月度云端离线配额与链接解析总量配额均为 `40 TiB`。
   - 每次调用 `instantCreate`（包含单文件秒传保存、链接面板临时预览、归档条目 `leaseDetail` 临时借出以及 `PikPakFileHandle` 过期重建）均按**原文件体积的 15%** 扣减上传流量配额；即使同一账号内已存在或刚删除相同 `gcid`，重复调用仍全额计费。
   - 免费账号月度离线流量虽同为 `40 TiB`，但受每日离线任务创建次数（约 3 次）与 `6 GiB` 总空间硬上限约束，且免费账号移入回收站的文件仍计入已用空间。
2. **签名直链生命周期**：
   - 服务端签发的原画与各转码档 CDN 直链（`DownloadLink.expiresAt` / URL `expire` 参数）真实有效期为 **24 小时（86400 秒）**。
   - 临时借出文件在调用 `deleteFile` 永久删除云端目录项后，已签发的直链在有效期内仍可持续响应 `HTTP 206` 分片读取。
3. **跨项目 SDK 边界**：
   - `pikpak-kotlin` 同时支撑不托管网盘目录、追求亚秒级起播的流媒体场景（Animeko）与完整网盘管理场景（Piko）。
   - 秒传（`instantCreate` / `leaseDetail`）在 SDK 层保持为一等公民且不修改默认语义；配额感知的路由决策全部收敛在 Piko 业务层（`InstantSavePlan`、`OfflinePackTracker` 与 `PikoMediaRepository`），SDK 仅按需补充通用并发裁剪能力。

## 二、整包离线链路提速

已收录磁链在服务端执行离线物化本质上是挂载既有内容对象，单文件或紧凑目录的服务端实际完成耗时通常仅为 `0.8` 至 `2.5` 秒。当前体感偏慢主要源于客户端轮询退避与串行目录裁剪，按以下三步收口：

1. **首阶段短突发轮询（`OfflinePackTracker`）**：
   - 现行逻辑在任务入队第 `0 ms` 立即查询一次 `getTask`（此时异步任务刚创建，必处于 `PENDING` 或 `RUNNING`），随后直接进入固定的 `3s -> 6s -> 9s` 轮询间隔，平白引入 `2` 至 `4` 秒空等。
   - 改为提交后的前 `5` 秒采用短突发阶梯轮询单任务接口 `getTask(taskId)`：`350ms -> 550ms -> 850ms -> 1300ms -> 2000ms`；若 `5` 秒内仍未完成（说明属于未缓存或冷门做种任务），再平滑退回 `3s -> 10s -> 30s -> 2m -> 5m` 长周期退避。
2. **单文件任务零裁剪直通**：
   - 当磁链仅含单个文件（`totalFiles == 1`）时，`getTask` 完成态返回的 `task.fileId` 即为目标文件本体，跳过目录探测与重命名步骤直接落盘完成。
3. **多级目录并行裁剪与异步收尾（`pruneOfflineOutput`）**：
   - 将产出目录树的逐层串行 `listFiles` 改为同层并发遍历，压缩多子目录合集的往返耗时。
   - 在临时借链播放场景下，一旦定位到目标文件并经 `getFile` 取得 24 小时签名直链即可立即启动播放器，将 `batchDelete` 清理临时产出文件与 `deleteOfflineTasks` 移交后台非取消作用域异步完成。

## 三、零界面概念的自动分流路由

界面层不新增「走离线还是走秒传」开关、不引入周转池容量配置、也不借道用户回收站避免污染回收站列表，全部由业务层按账号类型、包结构与剩余空间自动决策。

### 1. 链接解析保存路由（`InstantSavePlan`）

- **免费账号**：维持现有策略，已收录条目优先走秒传以节省每日离线次数并规避 `6 GiB` 整包空间门槛。
- **会员账号**：
  - 勾选小体积单文件（如总大小 `< 1 GiB`，15% 秒传消耗不足 `150 MiB`）时，继续走 `SaveRoute.INSTANT` 保持亚秒级落盘。
  - 勾选**大体积单文件**（`>= 1 GiB`）且网盘剩余空间足以容纳整包时，默认改走提速后的 `SaveRoute.OFFLINE_PACK`（单文件无需裁剪，约 `1` 至 `2` 秒完成，上传配额消耗为 `0`）。
  - 多文件选择沿用 `SaveRoute.OFFLINE_PACK` 并在完成后自动裁剪未勾选条目；剩余空间不足时回退秒传兜底。

### 2. 持久化签名详情缓存（`SignedDetailCache`）

- 将 `PikoMediaRepository` 的进程内短期详情缓存升级为按 `(account, gcid, sizeBytes)` 索引的本地持久化加密缓存：
  - 过期时刻取 `FileDetail` 内原画与可用转码直链的最小 `expiresAt` 减去安全余量（净有效期约 `23 小时 45 分钟`）。
  - 链接解析面板在 `Piko-Temp` 预览视频、归档条目借出或常规播放取回 `FileDetail` 时统一写入缓存。预览后执行「以引用保存」、24 小时内反复重开、切换清晰度、提取内封字幕、截取片段或唤起外部播放器均直接复用直链，零二次秒传扣费。
  - 当底层传输遇到 CDN `403` 或 `UrlExpiredException` 时，立即作废对应缓存项并回退常规续期重建链路。
- **本地完整播放缓存前置短路**：
  - 若 `PikoFileCachePool`（`.pplay`）已完整缓存目标媒体字节，直接走本地块源起播，跳过远端 `detailOf` 与 `leaseDetail`。

### 3. 归档条目点播路由（`VaultEntry`）

点播归档条目时依次执行以下无感决策：

1. **命中本地缓存**：命中 `SignedDetailCache`（24 小时内有效）或本地 `.pplay` 完整缓存时，`0` 配额即时起播。
2. **直走秒传借出（`leaseDetail`）的场景**：
   - 免费账号；
   - 小体积归档文件（如 `< 1 GiB`）；
   - 条目缺少原始链接（`source` 为空）；
   - **多文件大合集包**（例如包内文件数 `> 5` 或整包体积超过目标单文件的 `1.5` 倍，如整季番剧包或原盘目录）：整包离线需在服务端建大量目录节点并放大离线配额与临时空间占用，直接对目标单集执行 `leaseDetail` 秒传更迅速且经济；
   - 网盘当前剩余空间不足以容纳整包体积。
3. **走零上传配额临时取链的场景（会员账号 + 大体积单部影片或紧凑包）**：
   - **分享链接来源**：调用 `restoreShare` 将目标单文件转存至隐藏临时目录，`getFile` 签出 24 小时直链写入 `SignedDetailCache` 后立即后台永久删除临时副本（上传配额与离线配额均为 `0`）。
   - **磁力链接来源**（包内文件数 `<= 5` 且 `packBytes <= fileSize * 1.5`）：向隐藏临时目录提交 `createUrlFile` 并执行短突发轮询：
     - 若在快速窗口（如 `3` 秒）内完成，按 `gcid + size` 精确定位目标文件（无惧重命名），`getFile` 取回 24 小时直链立即起播，并在后台异步删除临时文件与离线任务记录；
     - 若超出快速窗口仍未完成（冷门未缓存资源），立即取消离线任务并无缝回退 `leaseDetail` 秒传兜底，确保起播绝不卡顿。

## 四、封面与元数据顺带补齐

- **本地内容元数据按内容键复用**：信息流（Clips）探测归档条目时，优先按 `(gcid, size)` 查询本地 SQLite `ContentMetadata`，对归档前已收录过转码与时长记录的条目实现零网络直出。
- **可选海报封面（`VaultEntry.coverUrl`）**：向后兼容扩展归档条目字段，串联 `MetaTube` 已解析出的 `cover_url`，并在归档目录挑选封面时优先采用目录内海报图片（`poster` / `cover`），其次 `coverUrl`，最后回退免签名永久有效的 `gcid` 视频截帧缩略图。
