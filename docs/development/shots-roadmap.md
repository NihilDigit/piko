# 截图基础设施的后续工作

`:shots` 要成为界面的回归基础设施，需要做到两点：整套跑得快，改了界面只重出受影响的图并列出变化。做到之前，
根目录 `CLAUDE.md` 不要求新界面补截图步骤与假服务端，也不要求收尾时出图审查。此项不阻塞发版。

## 现状（2026-10-08）

- `standardSet` 约 450 张，按 `ui-states.md` 的节排列，每个状态出桌面 1440x900、手机 400x860、平板 1280x800 三张，
  另有桌面窄窗口、手机横屏与深色。
- 已做：`:shots:renderAll` 分片并行（默认核数一半、至多 8 个子 JVM），画面连续 500ms 不变即截，整套由单进程约 48 分钟
  降到约 3.5 分钟；上一版留作 `build/shots-baseline/`，跑完写 `build/shots/changes.md` 与 `diff/` 下的并排对照。
  临时目录按主进程 pid 归属，每张图结束即删，子进程随主进程退出，启动时清理死进程的遗留；预置下载以真正的稀疏文件写入
  （原先 `RandomAccessFile.setLength` 在 NTFS 上按长度实际分配，一度占满 C 盘）。
- 已知不稳：设置页「上次同步于」用真实时钟；信息流走真实 libmpv、选段随机；M3 `LoadingIndicator` 每次停在不同形状。
  这几类连跑两次也会变，要在 ui 侧注入时钟或在减少动画时画静态样子才能消除。`drive-duplicates`、`panel-duplicates`
  桌面图的提示条停在「正在查找」。

## 待做

1. **按改动选图。** 截图进程挂 JaCoCo，每张图开拍前清空计数、拍完读出执行过的类，按类文件的 SourceFile 属性换算成
   `.kt` 路径，存成「图名 → 源文件」索引。之后用 `git diff <基线>..HEAD --name-only` 取改动的 `.kt`，只重出命中的图，
   再与上一版比对。几处兜底：
   - 公共组件（`components/`、`theme/`）命中面大，整套重出是正常结果。
   - 新增的 `.kt` 不在索引里：按其所在模块的图全部重出，或按引用它的已索引文件触发。
   - 常量内联、资源、依赖版本不在执行记录里：改了 `libs.versions.toml`、资源目录或 `shots/` 自身时整套重出。
   - 索引在每次整套运行时顺带刷新。JaCoCo 只在建索引的整套运行里开，约慢 1.5 倍。
2. **消除不稳的图。** 见上「已知不稳」，否则差异清单里每次都混着这几类噪声。
3. **失效步骤巡检。** 整套跑完列出「找不到」「等不到」的图名，作为界面改动后需要更新的清单。
4. **恢复要求。** 以上做完后，把根目录 `CLAUDE.md`「截图与界面审查」改回：新界面与新状态必须进截图清单、补假服务端，
   收尾时只看差异清单里的图，按本地设计规范镜像审一轮。

## 约束

- 交给 agent 时定死范围与时间：只做一项，验证只跑一次整套加一次按改动的运行，超过约 2 小时停下汇报。
  一轮整套几十分钟，反复全量对比会把时间耗在验证上。
- 长跑用 `installDist` 装出的副本，避免别处编译界面时 `NoClassDefFoundError`；多个 agent 不在同一工作区同时编译界面与跑截图。
