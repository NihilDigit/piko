本文用于审查本次跨 shared、ui、Android 和桌面的重构，说明设计约束、代码入口、验证方法与已知边界。
它与 [推进记录](interaction-refactor.md) 的用途不同：推进记录保留实验与阶段结果，本文按审查顺序组织。

**当前状态：上一轮重构已在本地提交，本轮多上下文交互仍是未提交的工作区改动。**
下方第 2—7 节以当前有效规则为准；第 8—10 节的 723 项完整回归和提交索引属于上一轮代码，
不能当作新交互已完成的平台验收。新增的专项与仍待完成的验证在第 12 节另列。
真实账号、全部设备和发布升级仍未验收；本地日志、测试产物与旧 release notes 草稿不属于源码提交。

## 1. 审查目标与判断标准

原问题是同一套前端状态被两种交互模型使用：桌面依赖标签，移动端没有合适的标签界面，
但资料页导航、恢复入口和一些业务执行仍沿用标签或页面寿命。
这会使“正在看哪里”“这项工作是否仍在执行”“结果到哪里找”互相影响。
星标、回收站入口故障与进度承载不一致是其中的具体表现。

本次设计要求：

1. 两端共用文件事实和业务规则，分别拥有导航与交互状态。
2. 已接受的工作不因离开页面而取消，页面结束后不执行晚到的界面回调。
3. 执行结果可以查询，提示消息不是唯一的数据来源。
4. 冲突先在统一动作入口拦截，按具体文件、目标目录或清单判断。
5. 停止、暂停、取消远端任务、移除记录和撤销分别遵循真实业务能力。
6. 结果不确定时，不能把“请求失败”直接解释为“服务端没有执行”。
7. 文件、查重与导入草稿按稳定上下文 ID 分别持有。切换或收起保留任务；关闭查重上下文才结束该次扫描。
   桌面可同时保留多个同类上下文，移动端只有一个主文件位置，辅助上下文在底部 sheet 分页、查重最多一份。
   手机 sheet 默认露出一截，上拉完整展开但主界面仍可见，最高档点「查看更多」进入全屏，返回恢复展开 sheet。

没有建立覆盖所有业务的通用事务、锁或调度器。
各业务保留自己的执行模型，任务页负责组合呈现。
审查时尤其注意：统一入口是否实际覆盖快捷键、拖放和确认后的调用，
而不仅是把菜单项变灰。

### 设计资料如何影响本次判断

本机 `docmirror4a` 的镜像用于阅读原始设计资料；镜像目录不是本项目运行依赖。
审查者可按下列官方入口补读。这里区分规范说明与本项目的设计选择，避免把实现推断写成规范要求。

| 资料 | 读到的原则 | 本次设计选择 |
| --- | --- | --- |
| [Material progress indicators](https://m3.material.io/components/progress-indicators/overview) | 同类过程采用一致配置，区分确定与不确定进度 | 两端共用 `WorkProgress` 的语义，任务行和详情呈现；没有总量不造百分比 |
| [Fluent progress bar](https://fluent2.microsoft.design/components/web/react/core/progressbar/usage/) | 进度说明当前任务及相关单位，关联步骤避免反复倒退 | 准备、提交、跟踪、后处理保留工作身份；阶段文案明确，无法换算的阶段不拼虚假总进度 |
| [Apple HIG tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | 顶层导航保持各区导航状态，导航入口和动作分开 | 移动顶层分区独立，具体浏览压栈；桌面文件标签另有稳定身份 |

HIG 的顶层 tab bar 与桌面文档标签不是同一种交互，不能用“移动端不适合标签”否定底部导航。
资料也没有要求所有长任务都放右下角浮窗。本项目将持续工作集中到任务入口，是基于多业务并存、
需要离页恢复和两端入口一致作出的选择；仍需用第 9 节的实际交互检查可发现性。

## 3. 状态所有权与生命周期

| 所有者 | 状态 | 保留 | 结束 |
| --- | --- | --- | --- |
| `PikoDriveRepository` | 文件事实、目录索引、查询缓存、变更通知 | 多个浏览上下文共享 | 账号数据切换，资源按 client 释放 |
| 桌面 `DriveWorkspace` | 文件标签的稳定 ID、路径/历史、滚动、高亮、剪贴板 | 页面组合重建、窗口隐藏 | 账号工作区结束 |
| `MobileFileWorkspace` | 单个主文件上下文、历史、滚动、高亮、剪贴板 | 配置变化；主位置按账号缓存 | 账号工作区结束 |
| `WorkspaceContexts` | 文件、查重、导入草稿的稳定 ID、顺序和活动项 | 桌面标签切换、移动 sheet 收起与重开 | 关闭对应上下文或账号工作区结束 |
| `WorkspaceViewModel` | 各 ID 的浏览/查重/导入会话、任务页状态、信息流与导航记忆 | 同账号界面重建；切换和收起不丢任务 | 关闭对应上下文或账号 ViewModelStore 清除 |
| `DriveBrowserSession` | 单个标签或返回栈页面的查询、搜索、多选、筛选、报告投影 | 标签或返回栈条目仍存在 | 关闭标签、出栈、账号离开 |
| `AccountExecutionScopes` | 已接受写操作的协程 | 浏览页关闭 | 活动账号结束、进程结束 |
| 每份导入草稿与 `AddLinkViewModel` | 各自的可编辑内容、解析/分享预览、选择与呈现状态 | 切换上下文、收起 sheet、跨页面 | 关闭该草稿或保存完成；已接受的保存按业务执行寿命结算 |
| 每份查重会话 | 对应根目录的扫描和报告；浏览会话独立保留筛选 | 切换上下文、收起 sheet | 关闭该查重上下文或账号结束 |
| 各业务 session | 工作身份、执行状态、远端引用、结果 | 没有页面订阅 | 各业务明确结束规则 |
| `InstantSaveRecords.attempts` | 秒传尝试的参数快照、逐文件回执与恢复关联 | 面板收起、离开文件页、没有提示订阅 | 同一 ID 转成功历史，显式移除或账号结束 |
| `ShareSaveSession` | 转存、远端任务、命名步骤与具体撤销关联 | 来源浏览页关闭、没有提示订阅 | 已确认结果最近 100 项，未知结果显式移除或账号结束 |
| `OfflineSubmitSession` | 离线请求预约、未知回执与无任务的即时文件回执 | 草稿结束、没有提示订阅 | 已知任务转交原有跟踪，其他结果显式移除或账号结束 |
| `PikoUploadCoordinator.preparations` | 上传准备、逐文件入队 ID、已建目录和未执行/未知结果 | 来源页面关闭、没有提示订阅；按账号投影 | 成功交给文件队列，已知失败最近 100 项，未知目录显式移除 |
| 界面/平台 scope | 焦点、动画、选择器、打开本地文件等回调 | 当前界面可用期 | 界面结束 |

AAC ViewModel 负责工作区寿命，不要求每个状态类都继承 ViewModel。
Compose State 用于同一 UI 线程上的呈现状态；StateFlow 用于可订阅的业务结果与平台工作信号。
审查重点是持有者、调用方向和释放条件，而不是某一种状态容器的使用比例。

`WorkspaceViewModel` 目前直接接收 `PikoServices`，`DriveScreenState` 仍是较大的查询/投影类。
这是当前可见的结构接缝；不能因为增加了 ViewModel 就声称所有分层问题都解决了。

### 两端导航实例

桌面 A 标签停在目录甲并选中文件，B 标签查看星标。B 的搜索、多选或关闭不能覆盖 A 的状态。
移动端主文件页停在甲，从信息流定位文件时打开独立 `Screen.Browse`，返回恢复信息流；
主文件页的搜索、选择和默认保存位置仍属于甲。
移动端不创建隐藏桌面标签来完成这条路径。

### 保存目标

`SaveTargetBinding` 将主文件工作区连接到外部上传等需要持续读取当前位置的业务。
新导入草稿在打开时把主文件目录固定为本次默认目标；随后文件导航不会改动它，用户仍可在草稿里另选。
资料页与临时 Browse 不覆盖主文件目录。
释放绑定按对象身份判断，旧工作区的释放不能清除新绑定。
目标目录已不存在时，沿用业务的 My Packs 回退规则。

## 4. 提交与结果模型

### 普通文件写入

`FileCommands` 验证动作可用性，提交不可变的 `FileWriteCommand`。
`FileWriteSession` 捕获账号与 `DriveWriteAccess`，页面只根据“已接受”清理选择或剪贴板。
随后页面关闭、切目录或切标签不更改目标，也不结束已经接受的操作。

创建、改名、移动、复制、恢复、永久删除与星标分别保留真实能力：

| 情况 | 结果/后续动作 |
| --- | --- |
| 写请求及实际文件状态都可核对 | 记录已确认子集 |
| 分批请求只有一部分确认 | 保留 confirmed、failed、notAttempted、unconfirmed 的区别 |
| 复制返回服务端任务 ID | 按该 ID 跟踪与重新查询 |
| 已提交但响应或后续查询丢失 | 保留待确认；阻止相关文件重复提交 |
| 新建响应丢失且没有新文件 ID | 不通过目录增量认领任意新文件，不提供虚假的只读核对能力 |
| 重新查询 | 只处理未知子集/已知远端 ID，不重新提交写请求 |
| 已确认的可逆改动 | 保存具体 inverse ID；后续新确认子集单独关联撤销 |

星标核对读取星标列表，不把不可靠的 detail.starred 当作真相。
批次每次最多提交 100 项，核对并发有上限。
copy 的服务端失败可能已经产生部分文件，不能把整个批次标为“什么都没发生”。

### 历史记录

`HistoryEditSession` 接收事件 ID，而不是屏幕上的文件 ID。
播放历史与最近添加独立；清空播放历史和该历史中进行中/待确认的移除互斥。
移除历史只修改事件及相关续播位置，不删除网盘文件，也不提供文件撤销。
清空响应丢失后出现新播放时，重新查询不能再次清空这些新记录。

### 秒传保存

保存意图包含固定的账号、接收目录、容器名称、源文件、最终名称及是否保留结构。
`InstantMagnetRepository` 在开始时固定 client 和参数，目录按路径由浅到深创建，文件并发上限为 4。
每个文件单独收集回执，一个失败不会取消其他兄弟请求并丢弃它们已返回的 ID。

| 情况 | 回执与动作 |
| --- | --- |
| 服务端返回新文件 ID | 该路径进入 confirmed |
| 写请求明确拒绝，或 SDK 确认内容不可秒传 | 进入 failed；单文件内容缺失保留原有免费确认/会员离线回退 |
| 写请求失去响应且没有文件 ID | 进入 unconfirmed，不通过目录增量认领任意新文件 |
| 创建子目录时失去响应 | 记录未知目录，文件记作未执行；不能再次创建该目录来重试 |
| 预览副本已移动，但后续改名失败 | 文件保存已确认，名称单列为待确认；不再保存一份来重试改名 |
| 同一预览副本对应多个同内容条目 | 该 ID 只消费一次，其余条目创建独立文件 |

失败后的重试沿用本次目录 ID 和命名快照，只选择 failed 与 notAttempted。
confirmed 和 unconfirmed 都不再次提交；有未知目录时停止自动重建路径。
批量空间核算只计重试剩余字节，不再次计算已经保存的整部视频或整包容量。
尚有待确认行时，不因其他行全部成功而发出整个批次已完成的结局。

任务页用 `instant:<id>` 表示运行期尝试及最终成功历史，同一次尝试的身份不变。
有尝试记录时，添加链接草稿的恢复动作并入它，避免同一件保存重复计数。
失败结果有路径清单与实际 ID；缺少远端标识的结果需要人工查看实际网盘，不能伪装成可自动核对。
冻结的保存计划保留在业务草稿会话，关闭呈现面板不清除它；明确放弃会话后，任务页仍保留本次运行期回执。

一个实际案例：视频秒传得到 ID V，字幕被明确拒绝。任务页显示视频已确认、字幕未保存。
从同一草稿重试只发送字幕；成功后复用原尝试 ID 转入成功历史，视频仍是 V，不创建第二份。
若字幕实际已创建但响应丢失，它进入待确认，重试按钮不发送该字幕。
同内容保存到另一个目录、容器或不同文件名仍可以独立进行。

保存发生后会发布目录事实变化，包含已经确认的部分及可能有副作用的未知目录创建。
因此其他文件页读取实际结果，不依赖来源页面完成跳转或显示 Snackbar。

### 归档清单条目

`VaultEntryEditSession` 接收真实清单目录 ID 与条目 ID，执行重命名或移除。
编辑同一清单的条目共用写入资源，进行中或待确认时阻止另一项编辑；不同清单独立。
跨目录移除按目录保存 confirmed、unconfirmed 和 notAttempted。

`VaultStore.committed` 读取可信清单，忽略乐观 pending 投影。
提交后失去确认时 `VaultWriteUnconfirmed` 携带该次实际尝试的 before/after，
用于后续核对和具体撤销；不能用最初页面列表代替冲突重试后的真实基线。
已经可信写成后的旧版本清理失败单独记日志，不将已确认编辑改报为失败。

### 解压与整树归档/恢复

解压工作使用操作 ID，文件 ID 不作为操作身份。待密码是输入请求，
已知远端任务可只读重查；移除本地结果记录不删除产出，也不等于取消远端执行。
完成记录不保留密码。

整树归档/恢复沿用自己的事务顺序与停止点。清点也属于正在执行。
停止在安全边界结束，已经完成的目录仍保留恢复依据与结果。
文件已恢复但清单尚未更新时报告部分完成，不能提供整项盲目重试。

## 5. 撤销与 UX 冲突规则

撤销是业务明确提供的反向操作，不能承诺所有请求天然可逆。
`DriveChangeJournal` 保留最近 20 项反向数据和最近 100 项撤销状态。
结果保存 inverse ID，不使用“撤销最近一次”代替“撤销这次”。
撤销状态通过同一原子快照发布；同一项重复点击只接受一次。
失败保留可用的反向数据，换号取消旧执行，旧 finally 与提示不能覆盖新运行期。
普通改名、移动和回收站恢复的撤销捕获提交时的 `DriveWriteAccess`。
改名撤销先读取当前名称，遇到后续其他改名就停止；回执丢失时只读核对是否已经恢复到旧名。
临时名互换会多次修改同一 ID，失败结果保留已确认的反向步骤数，重试从剩余步骤继续。
这仍不是服务端原子事务：其他客户端可以在检查与写入之间修改文件。

| 同时发生的动作 | 当前规则 |
| --- | --- |
| 同一文件的移动、删除、恢复与相关写入 | 在统一动作入口阻止已知重叠 |
| 星标与改名/移动/复制 | 允许，存在状态被删除/恢复改变时除外 |
| 相同源文件复制到不同目标 | 允许 |
| 向正在移动、删除、恢复的目录或其后代保存新内容 | 保存目标规则阻止，结果待确认时继续阻止 |
| 仅改名接收目录或其祖先，与向该目录保存新内容 | 允许；提交固定目录 ID |
| 移动、删除在途秒传、上传、云端离线或解压的接收目录及祖先 | 阻止；未知回执保留保护，需在任务页核对或明确移除 |
| 解压中的压缩包改名/删除 | 阻止；复制完整输入到无关目录、星标允许 |
| 整包处于 PRUNING 时改名、移动、删除产出树后代，或向树内新增内容 | 阻止；裁剪按相对路径永久删除未选内容，不能允许路径变化混入裁剪 |
| 整包接收目录内的无关文件、接收目录本身改名 | 允许；排他范围只覆盖已确认的产出树 |
| 已确认分享产出目录中的规范命名与外部文件动作 | 保护关联产出树及待确认命名对象，不只保护根对象 ID |
| 撤销接收目录的改名，与向该目录新增内容 | 允许；撤销元数据区分名称影响和位置/存在状态影响 |
| 分享、添加链接或外部上传的确认界面已打开后目标开始变化 | 确认提交前再检查规则；拒绝时保留原输入/上传请求 |
| 新建同目录同名文件夹 | 阻止重复进行中的请求 |
| 剪切粘贴被拒绝 | 保留剪贴板；接受后才清除 |
| 同一份归档清单的两个编辑 | 阻止，包含结果待确认 |
| 移动/删除正在编辑清单的目录或祖先 | 阻止 |
| 改名该目录，或修改无关真实文件 | 按 ID 提交不破坏清单语境，允许 |
| 归档/恢复某棵树与树内清单编辑 | 双向阻止已知冲突 |
| 根目录中的清单编辑与无关后代真实文件写入 | 不将根目录当作全盘排他锁 |
| 保存中替换/放弃添加链接 | 阻止；仍可收起面板 |
| 查看/关闭查重报告 | 不停止扫描；结束报告是另一个明确动作 |

祖先判断基于已知文件父关系与目录索引。它是本客户端可解释的 UX 防冲突，
不是对远端其他设备的全局互斥保证，也不能认领其他客户端的写入。
应继续按业务核对结果，不能因按钮已禁用就省略执行前的账号/身份检查。

`ReceivingActivity` 分别投影接收目录、正在使用的文件与裁剪产出树。它不执行任务、
不管理授权，也不建立跨业务执行队列。`FileCommands` 同时用于菜单可用性与最终提交检查，
`SaveTargetContext.actionChanges` 让已打开的保存/上传确认界面在规则变化后刷新。
普通云端提交交接后只保留 `OfflineReceivingTarget` 的账号、任务 ID、目录、产出 ID 与阶段，
不复制进度或来源 URL；任务列表查询、整包查询和已确认的删除/清空更新这些依赖。
列表未包含某 ID 不被解释为完成，离页期间未查询的旧依赖可能保持保护；进入任务页刷新即可核对。
重启后普通云端依赖在任务列表查询后建立，不能把尚未发现的远端任务当作本地已知事实。

秒传的逻辑容器身份是 `(账号, 父目录 ID, 容器名称)`；容器创建尚未确认时，
同名容器内即使选择了不同文件也会被阻止，避免重复创建目录。
目录回执确认后记录物理 ID，逐文件输出同时按已知根/子目录 ID 比较。
从父目录保存到新建容器 C 后，再直接进入 C 或已确认的子目录保存同一未知文件，仍命中保护；
其他文件和其他物理目录可以独立执行。移除回执只解除本地保护，不删除已经保存的文件。

## 6. 任务页、通知与资源边界

`TransfersState` 是异构任务投影，保留各业务类型与真实动作。
一个派生快照生成进行中、需要处理、已完成和产出已删除四组，同一 key 只分类一次。
计数、筛选、多选和空态读取同一分组，避免完成项仍残留在进行中。

任务页按上下文 ID 提供每份导入草稿、查重扫描/报告与清理的恢复入口。
桌面多个上下文并列成标签；移动端在标准底部 sheet 中分页，默认只露出一截，上拉完整展开仍可见主界面，
再点「查看更多」进入全屏，返回恢复展开 sheet。收起仍可恢复；关闭查重上下文才停止扫描并丢弃报告。
原桌面浮动进度卡、移动清理悬浮层与查重进度 sheet 已移除。
两端任务入口保持“任务”名称，速度/项数作为辅助信息。

`WorkProgress` 统一行、详情与平台通知的文案和进度含义。
没有可知总量时使用不定进度；等待输入时没有执行进度条。
前台 snackbar 提供便捷入口，运行期结果始终能在任务页找到。
后台结果通知按当前账号过滤。

清单缓存按 client 隔离，所有 IO 捕获同一 client。旧 client 的 pending、确认或清理
不能落到新账号的同名目录 ID，根目录空串尤其需要回归。
共享播放/下载缓存、临时借对象和预览文件仍需按它们自己的租约/引用计数释放。

分享浏览及选择由 `InstantSheetState` 中的 `ShareSaveState` 持有，转存执行由账号级 `ShareSaveSession` 持有。
浏览页只通过 `ShareCommands` 提交不可变参数，关闭来源页面不取消已接受的转存。
提交快照包含分享/来源 ID、目标与祖先 ID、命名选择，不保留提取码、passCodeToken 或签名直链。
任务页展示提交、跟踪、关联及命名阶段，保留成功、部分完成、失败和待确认结果；已有远端任务行不重复计数。

普通转存直接提交，不扫描目标目录。只有用户选择规范命名时才读取提交前基线。
服务端 `RESTORE_COMPLETE` 或已知任务 `COMPLETE` 才确认复制完成，目录根出现不能证明整树已经完成。
查询失败、超时或远端错误也不能证明服务端没有副作用；本次结果继续保留待确认的来源。
明确拒绝（如自己的分享、失效分享或需重新验证提取码）与未知提交分别处理。

自动命名在明确完成后才执行。关联要求新 ID、分享/来源标识匹配、类型匹配，文件还核对大小与可用哈希，
同一来源候选唯一，并在两次目录查询中保持相同 ID。已存在的同源副本、来源缺失、候选歧义均不认领。
目录内扫描失败或不完整时不对这棵目录执行规范命名。命名计划计入其他实际兄弟项，避免撞名。
这些来源标识不是请求 ID：没有完成回执时，即使唯一的新副本与源完全一致，也不能证明本次请求已执行，
更不能用它授权自动命名。完成回执下的关联也不提供跨客户端的全局请求隔离保证。

重新查询只读已知远端任务或待确认的名称，不重新转存或执行命名计划。
复制后来确认完成，但最初没有处理的命名仍列为未处理。无远端引用的未知提交提供实际目录入口，不伪装成可自动核对。
相同分享、来源、目标上的进行中/未知提交和待确认命名会阻止重复提交；移除记录不取消请求、不删除文件。
成功命名只记录具体步骤；临时名互换与后来确认的最终步骤追加在同一撤销记录中，防止分开撤销破坏依赖。
原反向数据过期时不能为依赖步骤构造不完整的新撤销；任务详情明确提示可用范围。

离线链接、整包与云端任务重新提交由 `OfflineSubmitSession` 记录提交边界。
它在请求前原子预约账号、目标、来源摘要的组合，相同在途或未知请求不能再次发送；其他来源或目标可独立提交。
磁力来源沿用项目的规范 infohash 身份，`dn`、`tr`、大小写和 Base32 写法不能绕过保护；普通 URL 保留完整字符串的区别。
提交固定 client，公开回执不含原始链接或签名参数。明确 4xx 拒绝可再次尝试，未知结果没有自动重发入口。
SDK `CreateUrlResult.InstantComplete` 表示响应没有 task 字段，本机源码注明其格式尚未固定。
应用额外要求就绪的单文件回执；空响应、空任务 ID、待完成文件和目录根不能作为保存完成证据。
需要整包清理与改名时必须取得任务引用，无引用的产出留供检查，不认领目录或执行删除。

取得任务 ID 后，既有云端列表或 `OfflinePackTracker` 接管，不增加另一套云端轮询或重复进度来源。
未知/拒绝及无任务的已确认单文件回执进入任务页，未知结果可返回原草稿或查看实际目录。
批量成功行移除、未知行保留；未知草稿的输入与保存目标冻结。重要结果可查询，前后台提示只提供便捷入口。
移除提交回执不取消远端任务，不删除文件，也不证明原请求未执行。
云端重新提交只有拿到成功回执后才删除旧任务记录，失败或未知时保留旧引用。
整包重试先将新远端任务接入持久跟踪，再清理旧任务记录；进行中标识覆盖完整交接，
等待旧 DELETE 时不能再次重试或移除正在交接的新任务。标识按账号和任务 ID 隔离，只存在于运行期，不修改已发布阶段枚举。
任务行和动作菜单读取同一进行中状态；Android 后台执行信号也包含这段本地交接。
默认 My Packs 的查询和创建使用捕获的 `DriveWriteAccess`，避免账号在两步之间切换后写入另一个账号。
本次没有修改已核对 v1.2.0 的 `OfflinePackJob` 序列化字段、阶段值或存储键；新提交回执为当前账号运行期记录，
不宣称跨进程恢复。整包已取得远端任务引用的原有持久化和续查行为保留。

预览通过 `PreviewTempFolder.Session` 记录实际创建的 ID。释放只删除原 client 的临时目录中
属于自己的文件：已经移动保存的文件、其他会话的预览和归档借对象不属于删除范围。
共享 Piko-Temp 目录保留；进程首次登录时另处理没有活跃预览的退出残留。
无法取得 ID 的失去响应请求只能留待残留清理，不能凭错误推断远端没有对象。
媒体借对象的临时目录请求也传入该媒体操作捕获的 client，避免清理或借对象改向新账号。

随机片段的即时详情缓存以 client 为边界，切换后清除；旧 client 查询晚到时不加入新缓存。
片段记录键包含账号。压缩包浏览的清单、密码记忆与建树状态按 client 换代，
请求完成时再次检查运行期；建树后的 NonCancellable 清理仍使用提交时的 client。
同账号重建 client 后，仓库使查询缓存过期，压缩包页面重新查询，前端导航上下文保留。

桌面关窗与 Android 使用同一后台执行来源，包含清理、查重、添加链接和分享保存。
等待密码、额度确认和结果待查仍可从任务页处理，但没有执行工作时不会单独维持前台服务。
桌面另由 `DesktopSessionPolicy` 判断是否仍有草稿、查重报告、待输入或需要处理的运行期结果。
这些状态存在时关窗进入托盘，执行结束也不自动丢弃它们；用户可显示窗口继续处理，或从托盘明确退出。
待确认的外部上传请求和等待下载额度确认也在保留范围内；取消/移除最后一个运行期上下文的变化必须能触发自动退出判断。
持久下载/上传的普通失败记录不要求保留整个进程。全部执行及运行期恢复上下文结束后才自动退出。
保存目标的统一判断由 `FileCommands.receivingAvailability` 提供，通过工作区 `SaveTargetContext` 绑定给添加链接、分享和外部上传。
`receivingChanges` 用于更新动作状态，提交前仍读取最新判断。目录改名与新内容写入保持独立，无关目标不被阻止。
运行期结果依然不是跨进程持久任务；明确退出或进程被杀后的恢复能力必须分别验收。

上传确认后先同步登记 `UploadPreparation`，再读取本地来源和建立远端目录，填入逐文件任务后才结束该阶段。
任务页、导航计数、平台进度和后台执行信号都包含准备阶段，因此“确认请求已清空、文件任务尚为空”不再是关窗退出空档。
准备使用冻结的选择和 client，逐文件入队、逐目录保存真实回执；后段失败不能丢掉之前已经准备好的文件任务。
结果区分已入队文件、已创建目录、来源读取失败、目录创建被拒绝、目录创建待确认和依赖目录的未执行文件。
同一子目录创建失败后不再次尝试它，其他独立目录和兄弟文件继续；空目录或全部来源不可读时不创建远端空壳。
SDK 返回空目录 ID 时不能作为成功处理，更不能把文件误传到空 ID 所代表的网盘根目录。

失败、部分完成、停止和未知结果保留在任务页，后台通知与前台入口是附加渠道。
相同账号、目标及来源摘要的在途准备，或已有已知/未知副作用的准备，阻止另一轮整包重建；其他来源或目标独立。
已入队文件由原任务继续，准备记录没有自动重建目录的重试入口。未读取成功且没有副作用的来源可以单独重选，
不会复制已入队的成功兄弟项。移除准备记录不删除目录，不取消文件任务，也不证明未知请求未执行。
确认框被拒绝时保留所选来源；账号变化后重新选择目标，旧界面回调不能向新账号提交。
入队事件携带账号及准备 ID，消费事件时再次核对账号；文件事实也按原账号发布。
恢复已发布的上传任务表之前不接受新准备；恢复后同来源、同目标的未完成文件任务应继续原任务，避免新建重复任务。

来源授权由准备、待确认输入和未完成文件任务共同持有，内部保留原始 URI，公开准备回执只保存摘要和相对路径。
授权登记与交还串行处理，本地遍历、读文件及云端请求不在这把资源锁中。
Android 树内文件映射到共同的树授权，不能在首个文件完成或准备结束时提前释放。
上传只申请读取授权；已有读写授权的目录还供下载保存位置等功能使用，不由上传释放读取权限。
文件夹准备失败或停止后，只有不再被输入/任务使用的授权才交还。
上传通知汇总同时观察准备、文件任务与账号；准备尚未结束时的队列暂空不触发整批汇总，换号也不交付旧账号的结果。

准备回执为运行期数据，不持久化；不能把已有逐文件上传会话的持久恢复能力套到尚未入队的准备阶段。
已核对 v1.2.0 的 `UploadTask`、状态枚举和序列化字段，本次没有修改这些发布格式或既有存储键。

呈现状态在串行执行约束下读写，并推进没有 Recomposer 时的 Snapshot 通知。

## 11. 用一轮真实业务路径审查调用链

以“选择种子内两集，保存到新目录，其中一项回执丢失”为例，测试不只检查 UI 文案：

1. `InstantSheetState` 从当前主文件工作区读取保存目标，冻结文件、目标、命名与目录结构。
   用户收起面板不改变快照；资料页导航不会覆盖主工作区默认目录。
2. 提交前经 `SaveTargetContext.availability` 检查目标，在 `InstantSaveRecords` 登记尝试身份。
   请求尚在建目录时，任务入口就能找到工作，不等单个文件入队才算“开始”。
3. 新目录回执返回 C 后，通过 `observeContainer` 记录物理 ID。
   此时改名接收父目录不改变 C，允许；删除/移动 C 或其祖先会被 `FileCommands` 拒绝。
4. 文件请求分别结算。服务端已创建 E01，客户端丢失响应时，记录 E01 为未知；
   E02 的成功 ID 继续保留。网络异常不回滚已确认的兄弟项，也不自动重发 E01。
5. 页面退出后由业务所有者完成结算。任务页同时展示已确认 ID、未执行/失败与未知路径，
   前台提示只是入口，关闭提示不丢结果。
6. 用户进入 C 再保存同一个未知文件时，物理身份比较仍阻止重复；其他独立文件可以提交。
   明确失败/未执行的原项可有限重试，复用已确认目录，不重新创建整棵树。
7. 用户明确移除未知回执后，本地保护解除，远端文件仍保留。这一步不是取消或撤销保存。
   自动化应断言实际请求数、目录数、文件 ID 与最终内容，人工应核对操作文案是否让人理解这一区别。

对应阅读 `InstantSaveReceiptSmokeTest`、`ReceivingReverseSmokeTest`，
再从 `TaskContinuations` / `TransfersState` 追到两端任务入口。
整包离线是另一条路径：它先接受整个种子，完成后在自己的产出树裁剪未选内容，
不能把秒传逐文件回执的成功条件或重试语义套到整包上。
