# 番号识别与规范命名

番号识别嵌在通用文件名解析里：视频、字幕、图片与原盘镜像先试番号，认出即按番号组织，认不出再走剧集解析。
规范命名在识别之上生成统一的文件名，经批量重命名与添加链接两个入口使用，一律先预览、可撤销，不做自动改名。

## 规则所在

番号相关的代码都在 `shared/.../shared/naming/av/`：

| 文件 | 内容 |
| --- | --- |
| `AvRules.kt` | 规则表与版本常量 `AV_RULES_VERSION`。识别结果有变时加一 |
| `AvMatcher.kt` | 识别流程。通用解析只经 `matchAv` 一个入口进来 |
| `AvInfo.kt` | 识别结果：番号、前缀、编号、类别、旗标、分段、片名；成套 A、B、C 的判定 |
| `CanonicalName.kt` | 单个文件的规范名 |
| `CanonicalBatch.kt` | 一批文件的规范名：字幕跟随、撞名区分、文件夹名 |

规则表写在 Kotlin 文件里，不写 JSON：`AndroidRegexGuardTest` 只扫 `.kt`，写进 JSON 的正则躲过检查，
到 Android 的 ICU 上才出错。正则一律写 `[0-9]`，不写 `\d`。

顶级域名只在 `SiteNoise.kt` 列一份，番号识别与广告判断都从那里取。无码、中字的通用写法由标签词表
（`Vocabulary.kt`）认，番号包只列番号片才有的旗标：单字母 U、C，leak，以及只在番号上才算无码的「流出」。
chs、cht 在词表里是简体、繁体字幕，对番号片都是中字；sub 只说有字幕，不算中字。

除文件名解析总开关之外，没有单独关闭番号识别的开关。

## 识别结果的约定

- 常规番号全大写，字母段与数字段以一个连字符相连，编号去掉前导零后补足三位：abc00123、ABC-0123、abc_123 都是 ABC-123。
- 厂牌番号保留原貌：FC2-PPV-1234567、HEYZO-0123、HEYDOUGA-4017-244、300MIUM-123、3DSVR-0123；
  日期番号照 MDC 的厂牌字典，加勒比用连字符（CARIB-021014-540），其余用下划线（1PON-092415_001、10MU-010120_01、
  PACO-010120_123、MURA-010120_123、CARIBPR-010120_001）。
- 分段一律写作 CD1、CD2：-1、_1、-A、part1、fhd1、hhb1 都归到这里，A 是 CD1。同一目录里同一番号有第一、第二段时，
  单独的 -C 是第三段而不是中字。
- 站点前缀（xxx.com@、kcf9.com-、[site.net]）、开头的 HD-、FHD- 与压制后缀（hhb、fhd、4K、H265、60fps）不进番号。
  方括号里整段就是番号时（`[FC2-PPV-1234567] 片名`）只拆掉括号。
- FC2 的各种写法都归到 `FC2-PPV-{编号}`：FC2PPV-、fc2_ppv_、FC2 PPV 、FC2-、FC2PPV 连写，编号 6 位、7 位照原样，
  不补零。分段（-1、_1、-cd1、part1、A、B）与压制后缀同常规番号。规范名保留 PPV：MDC 照原样保留，
  人手整理的目录也多这样写；MetaTube 的 number.Trim 会把它改成 `FC2-{编号}`，不影响刮削。

番号字符串用作查重键、作品键与播放列表分组，三者都只在内存里，没有持久化的数据依赖它们。
分段写法统一后，网盘列表与播放列表的行标题由「SSIS-123 1」变为「SSIS-123 CD1」。

## 命名规范

形状为 `{番号}{旗标} {片名}{分段}.{扩展名}`，如 `ABC-123-C 某片名-CD1.mp4`，没有片名时 `ABC-123-C-CD1.mp4`。

- 番号在最前：MDC 与 MetaTube 都从开头找番号。
- 旗标紧跟番号：中字 `-C`，无码 `-U`，两者 `-UC`。
- 分段在最后，写作 `-CD1`：Jellyfin 的多段合并认「名称-cd1」，不认没有关键字的 -1、-A。
- 压制标记不进名字。同目录两个视频得到同一个名字时，分辨率不同的各加 `[1080p]`、`[4K]` 这样的标签，
  仍相同的交给冲突检查标出。
- 片名里 PikPak 不收的字符（`/ \ : * ? " < > |`）换成全角同形字，制表与换行换成空格，去掉首尾空格与结尾句点。
- 服务端上限是 1024 个 UTF-8 字节；规范名另设 200 字节的可读上限，超出时只截片名，末尾加省略号。
- 字幕、音轨与图片的名字以某个视频的原主干加句点开头时，跟着换主干，后缀（`.zh.srt`）不动。
  自己带番号的字幕取同番号同分段视频的旗标与片名，语言写成 `.zh` 接在主干后面。没有通行写法的封面图
  （`abc00123pl.jpg`）跟不上视频时不改。
- 只含一个番号的文件夹改为 `{番号}{旗标} {片名}`。批量重命名里文件夹默认不勾选。
- 归档的虚拟条目不改。

片名取「再解析后不变」的写法：片名开头恰是标签词（「4K 片名」）时，规范名再解析会把它当后缀吃掉，生成时先按解析结果收敛。
因此规范名解析回来的番号、旗标、分段与片名不变，对规范名再求规范名得到它自己，`AvCanonicalNameTest` 以
`shared/src/desktopTest/resources/naming/av-names.tsv` 的样例逐条检查这两点。

## 入口

- 批量重命名：所选里有带番号的文件时，起手式多一项「按番号规范命名」。它是排在查找替换之前的一条 `RenameRule`
  （`CanonicalAvRule`），预览、冲突检查、执行与撤销沿用原有流程，查找替换可在规范名上继续调整。
- 单个文件：条目菜单「更多」里的「按番号规范命名」打开普通的重命名对话框，名字预填为规范名，确认即改，照常可撤销。
  配了 MetaTube 时框下多一行「从 MetaTube 取片名」，点了才查，查到就换成带这个片名的规范名；不在打开时自动查，
  多数时候原名里的片名就够用，查询要等外部站点。几项一起时仍是批量重命名。
- 命令面板：网盘页登记「按番号规范命名」，作用于选中项，没有选中时作用于当前目录的全部文件。
- 添加链接：资源里有会改名的番号文件时出现「按番号规范命名」，默认关。开启后列表行显示保存后的名字，
  秒传经 `instantCreate` 的名称参数直接以规范名落盘，不多发请求；移用的预览副本移出 Piko-Temp 后另改一次名。
  只含一个番号时新建文件夹也用规范名，用户改过文件夹名则以用户的为准。离线任务的接口没有名称参数，不改文件名。

## MetaTube 对接

规范命名可以从用户自己部署的 MetaTube 服务（metatube-sdk-go 的 HTTP 服务端）取片名。

- 设置的「刮削」一组只有「MetaTube 地址」与「访问令牌」两项，地址留空即不启用，此时界面上不出现任何刮削入口。
  地址按设备保存，不进设置同步；令牌按机密保存（Android 以密钥库加密存入偏好，桌面端存入系统保管处），同样不同步。
- 「测试连接」先取 `/v1/providers`（公开接口）确认连得上，再取 `/v1/db/version`（需令牌的接口里最轻的一个）验令牌。
- 查片名调 `/v1/movies/search?q=<番号>`，请求带 `Authorization: Bearer <令牌>`；只采用编号与番号一致的结果，
  搜索结果没有片名时再取 `/v1/movies/{provider}/{id}`。无码厂牌的番号搜不到时去掉厂牌名再搜一次。
  服务端哪里都查不到时回 404「info not found」，按查不到处理。
- FC2 搜 `FC2-{编号}`：服务端搜索前先经 number.Trim，这是它的不动点；FC2、FC2PPVDB 两个数据源再取纯数字当 ID，
  fc2hub 的 ID 是「视频号-编号」两段，不能直接按编号取详情。2026-10-08 对一个公共实例实测：各种写法在全部数据源里
  都回 404，指定数据源时 FC2 回 500「incomplete metadata」、FC2PPVDB 回 500，是数据源在那台服务器上取不到页面，
  与查询写法无关。指定数据源时出错回 500，不指定时被汇总成 404，`MetaTubeLiveProbe` 的 `fc2 query forms` 可复查。
- 结果按「地址|番号」缓存在进程里，查不到的也记下，出错的不记。并发 2 个，每次请求 15 秒超时；
  超时与错误照常返回失败，沿用原名中的片名，不阻塞改名。
- HTTP 走两端传入的 OkHttp 引擎，建客户端时取进程默认的 ProxySelector，代理设置照样生效。

Piko 不内置任何成人站点网址，也不内置、不推荐任何 MetaTube 实例：内容的来源与合规由部署服务的用户负责，
应用本身只是一个可配置的客户端。TMDB 的条款禁止用于色情相关应用，番号结果不发往 TMDB；TMDB 将来另起模块。

## 测试

- `AvNamingTest`：识别与成批整理；`AvCanonicalNameTest`：样例表、往返与幂等；`CanonicalAvRuleTest`：接入重命名管线。
- `InstantFlowSmokeTest`：添加链接开启规范命名后落盘的名字。
- `MetaTubeServiceTest`：MockEngine 顶替服务端，覆盖令牌、匹配、缓存与超时。
- `MetaTubeLiveProbe`：对真实服务端走一遍，只在本机手动跑：设 `METATUBE_PROBE_URL`（与 `METATUBE_PROBE_TOKEN`）后
  `./gradlew :shared:desktopTest --tests '*MetaTubeLiveProbe*' -i`，没设时跳过。FC2 的几种查询写法另设
  `METATUBE_PROBE_FC2`（纯数字编号）。
- Android 的 ICU 冒烟 `NamingUnicodeDigitsSmokeTest` 已包含 `canonicalAvNames`。
