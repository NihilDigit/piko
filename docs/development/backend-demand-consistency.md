# 后端需求传递与同步检查点

## 媒体详情与下载详情

2026-11-10 对信息流的两个真实文件只读查询：普通详情均返回可播放的 Original、1080P、720P、480P；同一文件的 `usage=FETCH` 返回空 `medias`。其中一个样本普通详情的原画媒体链接标示 `ms=81600000`，普通及 FETCH 的 octet-stream 链接均标示 `ms=5242880`，不能把 FETCH 当作完整媒体详情或普遍更快的播放入口。

媒体画质探测、归档租约详情及转码直链刷新使用普通详情；原画下载取链保留 FETCH。SDK 的 FETCH 预取缓存仅能满足同用途请求，不能交给普通 `getFile`。信息流的无转码负缓存以完整详情为依据，使用独立的序列化字段，开发期 FETCH 空列表产生的结论须重新探测。

## 传输需求

一个 `TransferDemand` 贯穿准备、API 排队、缓存读取与 CDN 准入。reader 绑定该需求后，其前后台分类跟随需求实时变化，不再由创建时的角色决定。否则候补片段升为紧迫需求时，会被自己触发的后台暂停策略阻塞。

缓存 worker 会在锁外检查需求成员关系，因此预取需求列表必须以不可变快照发布；不能在另一个协程持锁增删同一个 `ArrayList`。2026-11-10 信息流实测捕获了该路径的 `ConcurrentModificationException`，回归使用真实多线程并发注册、取消预取，而非仅在单线程虚拟时钟上执行。

API 等待队列也订阅需求变化，原地调整优先级并唤醒等待者；取消需求退还未使用的令牌预留。预取同时保留调用方的角色与基础优先级，候补原画仍比普通预取低一档，提升为播放需求后采用提升后的优先级。

信息流分别保存前台成员关系、紧迫阶段与播放意图，再计算有效优先级。更新预渲染邻居不能降级仍在等待数据的当前片段。

预读深度同样属于片段状态：准备完成前的扩展请求不能丢失；暂停仅暂时停止预读，恢复时重新应用保存的深度。邻居显式 hold 则停用它的预读，直到调用方再次扩展。

代理在单个 HTTP 请求已连续交付 256 KiB 后，可以使用调用方声明的预读窗口，即使播放器仍在等待首帧。短容器探测保持零预读；显式零窗口的暂停邻居也保持零预读。不能以“尚未出首帧”为由一直关闭当前片段的窗口，否则首次解复用会串行等待网络块。

缓存命中后的游标推进也必须检查窗口尾部。小块读取没有跨过当前块时，预读尾端仍可能跨过块边界；此时须唤醒 worker 获取新尾块，不能只在读头跨块时唤醒。

将预读缩为零时，仍保留 reader 已消费部分前缀的当前块，让它完成并进入共享缓存，同时截断后续区间。reader 关闭、撤回需求或离开该块后才可取消；否则已进入 HTTP 缓冲的后缀可能丢弃，随后下载又重取同一块。

空闲下载 worker 只能拆分尚未发出的区间计划。已发出 HTTP Range 的尾部即使未进入块缓存，也可能在 HTTP 缓冲中；将其转交新请求会重复传输。回归必须推进时钟，否则依赖经过时间的拆分分支可能从未执行。

## 原生播放器生命周期

片段退出保留窗口时撤回网络需求，通知使用它的播放器停止。代理 URL 和字节来源保留到所有使用者的 `stopAndAwaitIdle` 完成。每个播放器通过 `ClipPlaybackBinding` 串行换片；退休可以取消在途打开，清理作用域独立于页面。平台后端由调用方释放，不能在组合销毁时抢先关闭。

`ClipPlaybackBindingTest` 验证异步排空、换片及在途打开取消；`ClipRetirementNativeTest` 在真实窗口和 MediaMP/libmpv 上验证两次播放与退休，需显式设置 `PIKO_NATIVE_CLIP_TEST=1`。

MediaMP 0.5.0 的表面互操作对象异步初始化，初始空值也会产生 `skia interop unavailable` 日志。桌面日志保留实例标识、load/seek 代际及 `rendering … surface` 就绪消息，结合它们判断是否持续失败，不能仅凭初始报错认定可见画面黑屏。

## 同步分页实测（2026-11-10）

工具：`:cli:installDist` 后运行 `piko-cli sync-probe`，复用开发版会话。所有写入仅涉及本次新建的空目录，结束后移入回收站。

- 请求 `limit=2`，实际单页返回 400 条；探测因此创建 403 个子目录以跨过真实分页边界。
- 第一页返回 400 条，`sync_time` 为 `2026-11-10T00:14:38.891+08:00`，与该页最后一个探测条目的 `db_modify_time` 一致。
- 第一页后重命名一个已读条目和一个未读条目，并新建一个条目。
- 第二页返回 5 条，包含已读条目的新版本；末页水位为 `2026-11-10T00:14:40.469+08:00`。
- 合并后 404 个条目与批量详情一致。从首页面水位重放得到 5 条，从末页水位重放得到 0 条，两者都没有遗漏本次变更。
- 第二轮以四路有界并发创建样本，并显式校验批量详情返回了全部 404 个 ID，结果一致；首末页水位分别为 `2026-11-10T00:30:59.145+08:00` 和 `2026-11-10T00:31:02.694+08:00`，清理成功。

该结果支持当前接口按数据库修改时间推进扫描水位，而非为每页返回一个独立的响应时刻。保留末页检查点；只有全部分页及本地事务成功后才能推进。失败、取消和服务端游标过期不能提交部分结果。本次实测未覆盖同一数据库时间戳恰好横跨分页边界的情况。

SQLite 的完整性另有独立约束：历史同步时间和已有行不能证明当前索引完整。恢复文件或全局失效后，重启必须保留不完整状态，直至重新对账完成。

增量删除每页合并处理，递归从待删除节点驱动 `(generation,parent)` 查找。2026-11-10 开发版启动实测中，SQLite 原计划选择 `tree_folders(generation)` 并反向连接，遇到大量本地不存在的墓碑时反复扫描 65,037 条记录；提交持锁又阻塞了主线程的账号代际读取。递归使用 `CROSS JOIN` 固定父节点在外层，删除根按 256 条分批；账号代际直接读取不可变 StateFlow 快照。`DriveTreeDeltaTest` 同时校验实际查询计划包含 `parent=?`、批次数及数据完整性。

## 写操作撤销基线

重命名和移动在排队前序操作结束后读取已确认基线。本地列表或树索引尚未恢复时，通过绑定账号的文件详情接口补齐原名与原父目录，再执行修改，避免服务端修改成功却没有可撤销记录。查询失败时不继续提交缺少基线的修改。

## 日志口径审查与待完善约束

以下是当前实现的观测缺口，不能当作已经完成的日志契约。

- 播放位置推进是媒体时钟证据，不是首帧呈现。信息流与普通播放器的定位日志用墙钟耗时减去固定媒体时长，会受倍速、时间戳跳变和采样影响而出现负值。应分别记录墙钟耗时、位置增量、倍速和观测事件，不能以截断负数代替修正定义。
- 信息流“打开”耗时从等待媒体准备之前起算，实际包含准备时间；`Ready` 又是后端事件，不是可见帧已经呈现的证明。准备、排队、后端加载、表面就绪和播放位置推进应各用自身起止事件，明确累计耗时与阶段耗时的区别。
- `PikoDownloadCoordinator` 的“下载”速率汇总共享文件缓存，包含播放和预取流量。应区分缓存网络接收与下载任务落盘进度，不能把共享字节重复归属于不同消费者。
- `TransportSummary` 在请求结束时计入整条请求的交付字节，窗口速率不是该时间段真实接收速率。长请求、空闲期和请求取消会使它偏离实时吞吐。真实速率应来自累计字节计数采样；结束事件用于请求结果和延迟分布。
- `RangeAttempt` 的在途数采样发生在自身准入之前，不能称作在途峰值；优先级来自读取创建时的值，不能代表准入时或后续提权后的值。准入等待已有内部计数，却没有进入对外事件；RangeReader 的外层退避也未包含在仅描述 HTTP 层重试的 `retryBackoff` 中。
- 每条重试应能关联读取身份与尝试序号，并记录 HTTP 状态、退避时长、实际准入优先级、容量变化及退出原因。共享缓存还需要独立身份，允许同一字节服务多个消费者。
- 关闭流程须记录需求撤回、原生 stop 请求、idle 确认和代理注销，并携带原因。原生报错应保留原始级别及发生阶段，不能把全部退出期错误当成播放故障，也不能无条件忽略它们。
- 原生实例地址会复用，单独使用地址不能构成长期会话身份。日志应记录逻辑会话和 load/seek 代际；原生日志未提供代际时，只能记录接收时的上下文，不能声称它一定属于该代际。
- 全局手机号正则会误删字节偏移和文件长度。可信数值字段应按类型格式化，未知文本仍需脱敏；Android echo 目前先于文件脱敏执行，两个输出通道须遵守相同隐私规则。
- 日志事件与字段不随界面语言切换；避免“画面走起来”“备会话”“送出”等含义不明确的表述。原生消息去重应有时间窗口和重复计数，不能无限期吞掉相同错误的再次发生。

限流恢复另有需要回归验证的路径：`SignedUrlGates` 降低容量后，任何成功请求都会增加上限，包括降档前已在途的请求，可能立即抵消回退。应验证同一轮拥塞反馈与恢复资格，而非仅调整退避常量。画质探测失败也应与“服务端确认无转码”分开，未知结果不得写入无转码负缓存。

TS/HEVC 诊断需覆盖同一片段的首次打开、片内 seek 和播放器槽位复用。至少记录切片范围、经校验的接入点、视频编码与接入帧类型、首尾 PTS 和播放代际；仅凭 `PPS id out of range` 或 `PES packet size mismatch` 不能判定是源文件损坏、切点不足还是切换时残留状态。
