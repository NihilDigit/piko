# 信息流

刷**网盘页当前文件夹**里的视频，子文件夹里的也算，其余一切都为刷得顺服务。会话与取流在
`shared/.../shared/state/ClipFeedSession.kt`、`ClipStreams.kt`。

宽窗口是网盘页右侧的侧栏，放不下时全屏，桌面端还能弹出到独立窗口。范围在打开的那一刻取定；进子文件夹不换。
离开这个文件夹（路径栈里不再有它）、桌面的右栏让给添加链接，都是挂起，与「在网盘中显示」同一种状态（`suspendFeed`），
不收起；独立窗口不挂起，但收回主窗口时右栏若被添加链接占着，同样挂起。添加链接停在右栏时信息流打不开、继续不了，
关掉添加链接后也不自动继续，规则与理由见 `ui/CLAUDE.md` 的「右侧那一栏」。不要再加范围菜单或「订阅」一类的入口。

## 挑段的先后

目标是连着的几段出自不同的文件夹、不同的作品，同一个文件的两段隔得更远。在 `ClipFeedSelection.kt` 的
`selectFeedCandidates`，`fillAhead` 每次挑一批（至多 8 段，挑中后查转码）接到候补末尾：

- 先筛：同一内容（gcid）只留一份；队列里已有的、最近看过的不挑，「最近」是至多 50 段、视频不多时为一半；
  遍历没走完时只挑这一轮还没出过的。
- 文件夹按比例隔开（`folderPace`）：有 k 个视频的文件夹至少隔「同一内容的间隔 / k」段才再出。
  只靠代价罚不住：大文件夹多是同一部番，每连出一段文件夹与作品的代价一起涨，小文件夹被一段接一段地提前用光，
  此后在同一内容的间隔里一直轮不到，留下大文件夹连出十几段。
- 其余之中挑代价最小的（`FeedCost`）：所在文件夹、作品在最近几段里的热度，内容已出过几次，只有原画，在子文件夹里，
  加一点随机。转码与当前层从此只是倾向：分档时有转码的挑完才轮到原画，有转码的番剧文件夹会一直排在前面。
  作品取自网盘页同一套文件名解析（`analyzeDriveFolder` 的作品块），同一部番分在几季的文件夹里也算一部；认不出的各算一部。
- 遍历没走完时留位（`FeedHold`）：补队列只认已列出的目录，打开时一口气要补二十几段，不留位就全补成最先列出的
  一两个文件夹（改前头 10 段平均只出自 2.3 个文件夹）。列出的目录不到 8 个时每个文件夹在队列里只排一段，
  此后至多两段；队列不到留位下限时照常补，首段仍是第一个列出的目录里的头一个。

比较过而没用的：按文件夹轮转（一视同仁，小文件夹很快挑完，剩下的全出自大的）、按文件数加权抽样（只管比例、不管相邻，
大文件夹占九成时成串地出）。改挑法后用 `ClipFeedSpreadSmokeTest` 在构造的目录树上打出前 30 段对照
（`PIKO_CLIP_SIM=1`，结果写到临时目录的 `piko-clip-sim.txt`）。

在信息流里「在网盘中显示」是「刷到有趣的，去研究一下」：信息流**挂起**（队列与看到哪一段都留着，应用内不画），
出发点记成 `DriveLocation`，之后左边的浏览是临时的，离开文件夹也不收起；网盘页底部的 `FeedResumeBar` 给「继续刷」
（`returnTo` 连历史一起回到出发点，临时浏览整段丢掉）与关闭。只有关闭才清空队列（`ClipFeedSession.close`）。
换号与退出登录等于关闭，挂起着的也是（`endAccount`）；队列按账号与文件夹存盘，切回原账号、在同一文件夹再打开时接着放。
有标签栏时这段浏览开在单独的标签里（`feedDetourTab`，标签栏上是信息流的图标、第三色）。继续刷只切回原来的标签，不关它，
下次跳出来仍用它，始终只有一个；关掉信息流后它成为寻常的标签。
路径不问服务端：遍历时列到的文件夹都记进仓库的文件夹索引（`FolderIndex`，与网盘页同一份，改名、移动后跟着变），
`ClipFeedSession.pathTo` 据此当场拼出；用到的那几层随队列存盘，重开时补进索引的空缺（`seedFolders`）。拼不出时才逐级查，
那几秒里整个窗口盖着 `LocatingOverlay`、不接输入，否则人在原处做的事会被晚到的跳转盖掉；传输页与我的分享同用这一层。

取流的调度：每段只预取切片开头 5 秒（`PreparedClip.sliceRanges`）；放过 3 秒才升档，播放器的缓冲（`setBufferAhead`，
mpv 的 cache-secs）与代理的预读一起放开到 10 秒，此前两者都压着。播放器的缓冲读在 SDK 里是最高档，不压就越过所有预取。
冷开时头一段画面走起来之前只备前三段（`COLD_START_CLIPS`）。各段的会话与预取（`ClipStreams`）挂在 `ClipFeedSession` 上，
不随页面走：Android 上「看完整」压栈时信息流离开组合，回来不必重取。取不到的一段先挪到队尾重取一次，第二次才拉黑。
原画开头比转码开头低一档（7 对 8），不要改成独占通道：一段直链坏了会把其余原画全堵住。
「当前页」一松手就取 `targetPage`，不等 `settledPage`：手机上吸附动画收尾要几百毫秒，等它就是每段起步顿一下。
SDK 的阻塞读分两档：`PikPakStreamReader.urgent`（拖动后、卡顿、未出首帧）是 100，播放器平时往后缓冲是 50；
「有人在等」由界面判断后设上，桌面端后端拖动时不报缓冲，拖动要单独记。

画面分三层：最底是三个播放器的画面表面，按页码跟着翻页平移；中间是翻页器，页是透明的，只画属于那一段的东西
（就绪前的缩略图、暂停标记、缓冲转圈、双击的星）；最上是控件层（说明、操作栏、进度条、底部遮罩）与顶栏，固定不动，
只画当前段，换段时就地淡出淡入。控件不要再放回页里：翻页途中两段的说明连同遮罩一起滑过画面。
沉浸（`ClipFeedSession.immersive`，会话内保持、不存盘）藏起控件层与顶栏，单击只叫回控件、不暂停，也不认双击，
免得叫回要等双击判定的那一拍；长按倍速与翻页照旧。
区域高度不到 480dp（横握的手机）时控件按横屏排：操作栏在右下横排，说明限宽；画面一律完整显示、两侧垫模糊背景，
不按比例相近铺满（约 2.2:1 的屏幕上 16:9 落在容差内，会裁去上下近两成）。这时信息流独占整个窗口，侧边栏连窄轨也不画
（`PikoMainScaffold` 的 `feedCoversWindow`）：手机横过来宽度够侧边栏，否则左边留一条窄轨。看高度不看宽高比，桌面的独立窗口
与侧栏够高，照竖屏排。Android 顶栏另有横屏按钮（`PikoPlatform.rememberLandscapeLock`，SENSOR_LANDSCAPE），
系统锁定自动旋转时靠它转过来，状态同样记在会话上（`landscape`）。看完整之前先当场放开：播放器在组合时就记下当前方向、
退出时恢复它，放开晚了它记下的是横屏，退出后一直锁着。
