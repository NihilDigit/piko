# 网盘页

通用的界面约定见 `ui/CLAUDE.md`，状态在 `shared/.../shared/state/DriveScreenState.kt`。
下文的「宽窗口」指桌面的交互模型（有标签栏、命令栏），「窄窗口」指移动端，平板也算，不看实际宽度，见 `ui/CLAUDE.md` 的响应式布局。

- 库：最近添加、星标、播放历史与回收站不是单独的页，是网盘页里的位置（`DriveLibrary`），列表、视图、属性、
  多选与右键菜单全用网盘页的。它占路径栈的第一级、取代根目录（`[星标]`、`[星标, 某文件夹]`），ID 带 `piko:` 前缀，
  后退、标签、恢复上次位置因此照常工作。`DriveScreenState.libraryView` 为眼前列的是哪个库，`load` 据此改从星标、
  回收站或事件接口取；库里平铺不解析、不折叠、不给排序，不能新建、上传、粘贴，也不接拖放。回收站只有恢复与彻底删除，
  最近添加与播放历史多一个「移除记录」，各库都多「在网盘中显示」。侧边栏里它们是开关：停在这个库时再点一下回到打开之前的位置。
  我的分享列的是链接不是文件，仍是单独的页。
- 压缩包也是位置（`ArchiveLocation`，ID 以 `piko-archive:` 开头，带着压缩包的 ID、gcid 与包内路径）：单击 zip、rar、7z 是进去看，
  不再是下载，分卷照旧。包里逐层经 `listArchive` 列出，平铺、只读，能做的只有打开、下载文件与解压选中的几项（主操作「全部解压」），
  解压照旧落在压缩包旁边。状态在进程级的 `ArchiveBrowser`：密码与列过的层不随网盘页重建丢失。要密码时先逐个试存过的
  （列目录只是一次查询），都不对才弹框，取消即退出压缩包。存标签与最近去过时截到压缩包之前，重启不回到包里。
  包里的文件与归档条目一样按 gcid 借对象打开（`LeasedFile`），播放、下载、预览不分来源。从没解压过的包不给 gcid，
  第一次打开时先引导解压一次（`ArchiveRepository.prime`，实测与理由在那里），几秒，之后这个包都直接借。
- 查找重复也是这样一个位置（`DriveLibrary.DUPLICATES`），不在侧边栏里，原来的面板已去掉：用户反馈面板里看不到预览、不好挑。
  点「查找重复」人留在原处（`findDuplicates`）：曾经点了就跳进这一页，几分钟里只有转圈，像整个界面被占住。
  有标签栏时在后台开一个查重标签（`DriveTab.isDuplicates`），标签上转圈、扫完显示结果，切过去就是这一页，关掉标签即结束查重，
  查重结束时标签随之关掉；考虑过在右下角卡片展开成浮动面板放结果，否决了：等于在窗口里另做一套窗口管理，还要把网盘页拆成可复用的组件。
  没有标签栏时扫描在网盘页底部的 sheet 里（`TaskSheet.kt` 与 `DuplicatesUi.kt` 的 `duplicatesSheet`）：扫描、比对、失败与没有结果都在 sheet 上，
  进度从头到尾是同一根不确定的线性进度条（服务端不给目录的子项数，总量事先不知道；超过 5 秒不用 loading indicator）。
  可以收到部分展开回文件夹里看；sheet 展开着扫完且有结果就压栈进结果页，收着时 sheet 上给「查看」，不把人拽走。
  往起点所在的那棵树外走（返回、面包屑、从别处跳进网盘、快速访问、「我的」里的库、命令面板）会结束查找，先确认「结束查找重复？」：
  宽窗口里结束查找是关掉它的标签，一个显式的动作，窄窗口里离开是顺手的一下，确认把它变成显式的。进起点的子文件夹不算离开，
  切底部标签也不算；进了结果页，离开结果页同样先确认。sheet 上的 × 本身是显式的，不问；换账号这类不是人走的静默结束。
  拦在仓库换栈之前（`PikoDriveRepository.leaveGuard`，由主界面装上 `TaskSlot.allowsLeaving`），确认后再把同一步走一遍：
  不要改成换了栈再跳回去，那样历史里多一步、画面会闪。锚点记在 `TaskSlot.duplicatesAnchor`。
  取消就等于什么都没发生，确认就做完整个动作：除了换栈还有别的步骤的入口（先切到网盘页的「我的」里的库、在网盘中显示、
  快速访问、命令面板，跳过去后标出某一项的 `revealInDrive`）走 `PikoDriveRepository.navigateThen`，按目标先问、重走的是整个动作；
  只靠换栈时那一问，取消时页已经切过去，确认后标出那一步也丢了。新加这类入口照做。
  内容来自进程级的 `DuplicateSession`，不经网络，每组一个分区标题；同一个文件可能
  在两组各占一行，列表项的 key 带上组。选中的单位是文件：选中它两行都勾上，删除只删一次；收起的组与收起的分区一样算进全选。
  建议移走的（完全相同的组里保留那份以外的，版本组不建议）在位置一栏注明，
  「选中建议移走的」是这一页的主操作（`PrimaryAction`）。不在进来时自动勾上：那样一进来就在多选里，单击变成勾选、播不了，点空白处勾选又没了。勾选与
  移入回收站就是网盘页的多选与删除。结果是扫描那一刻的快照，`DuplicateFinderState` 订阅撤销日志，移入回收站的拿掉、
  撤销回来的补回，再重新分组。离开后从查重标签回来；没有标签栏时离开即结束（先确认）。
- 按番号规范命名一个文件夹（`DriveLibrary.CANONICAL_NAMES`）与查找重复是同一种形态，规则与理由见 `docs/development/av-naming.md`：
  进程级会话（`FolderTaskSession`，状态 `CanonicalNamingState`），宽窗口是后台标签，窄窗口是独占 sheet 加结果页，
  离开那棵树先确认。两者共用的部分只写一份：位置的内容经 `SessionListing` 交给 `DriveScreenState`（`DuplicateListing`、
  `CanonicalListing`），会话标签经 `DriveTab.session` 认、由 `PikoDriveRepository.sessionTabHeld` 占住，标签上的样子是
  `SessionTab`，窄窗口的锚点与 sheet 的档位是 `TaskSlot.placeTaskAnchor`、`placeTaskExpanded`（同一时刻只有一件，见 `Task.followsPlace`）。
  再加这类位置照这几处接上，不要另写一套。结果页的行是真实条目，行标题换成规范名（`DriveFileView.title`），
  原名照下面「名字」一条写在行标题下，所在文件夹在行下面那一栏；主操作在多选里也在（「应用所选」），不像查重那样多选时让给命令栏。
- 收起而没做完的东西不再收进命令栏右端的「收着的东西」菜单（已删）：那是一张竖排菜单，点一项就跳走，看着像操作、实为导航。
  现在宽窗口的添加链接开着时在右栏（放不下时是浮动的侧边面板），收起后是右下角的浮动卡片（`FloatingTasks`），更窄时是底部 sheet 停在部分展开那一档；下载片段不能收起（关掉即放弃，改过区间的先确认），
  挂起的信息流由命令栏「信息流」按钮上的小圆点提示。
- 宽窗口的命令栏：每一样显不显示由 `DriveCommands.kt` 的 `driveCommands` 按规则算出，输入是在哪、作用于哪几项、
  剪贴板与眼前列表的情形。做不了的不摆，别处已经摆着的不重复。
  加按钮先在那里加规则，不在命令栏里零散判断。放不下时由 `CommandBarLayout` 按优先级把低的收进「更多」
  （M3 toolbars 的 overflow），收哪几项只看宽度，拖动窗口时不跳；显示什么仍只由规则决定。
- 顶栏：桌面照资源管理器：后退、前进、上一级，加一条地址栏（`DrivePathTitle`，每段能点、能接住拖来的条目）；
  地址栏的首段照栈底写：在库里是库名与库的图标，点了回到库本身；库名后面没有 ›，库不是有子文件夹的一层。
  移动端是目录名作标题，副标题是分区跳转（`SectionJumper`：结构化列表里眼下滚到的分区，点开跳到别的分区），
  不另放面包屑：往上走靠返回，栈导航一层一层退回去。
- 目录图（`FolderMap.kt`，issue #18）：只在宽窗口里有，一块浮在列表上的面板，里面是从网盘根起的树，文件夹与文件都列，
  展开到眼前的位置，引导线连起父子；最内层的文件夹文件多于三个时只列三个，末行「还有 N 个文件」，展开后末行是「收起」。
  能当文件夹打开的压缩包是可展开的节点，要密码时点那一行进到包里输。点文件是先到它所在的文件夹再当作在列表里单击它。
  按住标题行拖到列表里任意处，四边四角拖着改大小（停靠那一侧的边与角除外：那里正压在把手上，悬停展开时光标一落下就成了改大小），拖动区一半在卡片外，悬停换成改大小的光标，不画把手（`FloatingPanel`，与属性卡片共用）；用普通 `Layout` 浮在列表这一块里，不用 Popup：不抢焦点的 Popup 收不到键盘。
  开着与钉着是两个独立的偏好（`folderMapOpenFlow`、`folderMapPinnedFlow`，每台设备各自的，不同步），跨重启记住。
  开着与否由 ×、导航栏搜索旁的树形按钮（只在关着时出现）、主修饰键+Shift+E 与命令面板改；钉着与否只由标题行的钉住按钮改，
  别的动作一律不碰它，× 关掉再打开照旧钉着（曾经做成三态、拖动打字顺手钉住，用户没按钉住却被记成钉住，关掉又丢了钉住）。
  钉住时打开即常驻，跳转、点列表、指针离开都不收；没钉住时停靠在边沿的面板不用就收成贴边的把手：贴着面板停靠那一侧的
  列表边沿、上沿与面板对齐、右侧让出滚动条，与面板同一种容器色、带阴影，中间一个目录树图标，可 Tab 到（读屏念「展开目录图」）。
  之前只画一道 4dp 的半透明竖条，手测几乎看不见。指针在把手上停住片刻是临时展开，离开即收；点把手、触屏轻点、导航栏按钮、
  快捷键、命令面板、把手上按回车或空格也是临时展开，键盘展开时焦点进树。主动打开时指针多半在别处，要等它进过保持区一次
  （或面板里忙过一次）才开始按离开计时，否则从导航栏按钮那里打开，半秒就收了。临时展开时按钮钉住转为常驻；
  取消钉住时指针在保持区里转为临时展开，不在就收起。Esc 与快捷键在临时展开时是收起（焦点在面板里时先还给列表）；
  钉住时 Esc 只还焦点，快捷键是关掉（同 ×，钉住照旧），收成把手会像取消了钉住。× 是关掉（导航栏的按钮重新出现）。
  时机全在 `FolderMapAutoHide.kt`：纯函数状态机加 `FolderMapTiming` 常量表，测试在 `desktopApp` 的 `FolderMapAutoHideTest`。
  停住满 200ms 才展开（起初是 400ms，手测嫌慢；在打开区里挪超过 6dp 重新计时，按着键时不计，拖滚动条、框选经过不会弹）；
  保持区是面板外扩 24dp 连同把手，离开满 500ms 才收，期间回来即取消；正在拖标题行或改大小（按手势的开始与结束）、
  面板里有键盘焦点、过滤框有字或有焦点时不收，解除后从头计时；收起后指针要先离开打开区一次才重新武装，停在边沿不会弹回。
  时长是意图过滤，不随减少动画归零，只有动画跳切。这些数值用户逐条定过，改之前先问。
  展开是在原位淡入加 8dp 位移（`PikoMotion.peekEnter`，桌面 167ms），收起只淡出（83ms）。
  只有停靠的面板自动收起：松手时左沿或右沿离列表同侧边沿不超过 48dp 算停靠，拉窗口后重判一次，拖动途中不判、不吸附；
  停在左沿的改为跟着左沿走。拖到中间的面板常驻，Esc 只把焦点还给列表；钉住按钮照旧在，只记偏好，没钉住的拖回边沿又按临时展开算。
  收起时面板离开组合，过滤、高亮与滚动位置在 `FolderMapState` 里，展开回来原样；位置与 `bounds` 留着，属性卡片照旧按它避让。
  开发构建可描出打开区与保持区、角上显示状态、钉住与否与倒计时：`JAVA_TOOL_OPTIONS=-Dpiko.debug.folder-map=true` 再 `:desktopApp:run`
  （`PikoPlatform.debugFolderMapZones`，带版本号打的包里不认）。
  每层的列表与网盘页共用仓库的列表缓存，进到目录图里展开过的文件夹是当场出来的；网盘里有改动时由 `FolderMapState.onChange`
  重列受影响的层，不只在换了位置时才重新展开。树里没有根目录那一行，标题行「过滤」之前的主页按钮回到根目录，与命令栏的主页按钮
  同一个入口，已在根目录时不显示。
  否决过的形态，不要再试：地址栏 › 召出的弹出版（藏在分隔符里没人找得到）；侧边栏里的导航窗格（240dp 放不下五六层缩进）；
  网格旁单开一栏（让出位置时网格反复重排，且是侧边栏旁边再并排一栏导航）；贴右沿的缩略图细轨，悬停展开、与树同一个容器形变、
  拖到任意位置（碰到的东西当场变形、拖的与停下的不是同一个东西，补了延时、吸附鼠标仍别扭，细轨上放按钮又难看）。
  现在的自动收起与那一版的区别：细条与面板是两个节点，面板原位淡入、不形变；指针要停住才弹，不是路过即弹；打开区与保持区
  分开、离开有延时，收起后要先离开才重新武装；拖动只在展开态、拖着时不收，停靠只在松手时判，拖动中不吸附；把手整条是一个入口、
  只放一个图标，不在上面摆几个按钮，钉住按钮在面板标题行。那一版还否决过钉住开关（面板能随便拖、打开就一直开着之后用不着），
  这一版重新加回，是因为有了自动收起，钉住才有了对立面。窄窗口不做：手机上栈导航与返回已够用。
- 条目的操作：每一样只在 `DriveActions.kt` 定义一次（图标、标签、分档、分组），单项与多选的右键菜单、操作面板、命令栏、
  移动端多选顶栏与播放器的文件操作都从那里取；做不做得了由 `DriveCommands.kt` 的 `itemCommands` 定，命令栏的 `driveCommands`
  也由它算出，两边不各写条件。一项或几项的全部操作只在 `DriveScreen` 的 `operationsOf` 构造：回收站、压缩包里、多选、
  归档条目各走一支，其余经 `fileActions` 按类型加。面板只看它自己那一项，右键菜单作用于 `targetsOf`。
  图标行是下载、分享、星标、重命名；常驻是移动到、复制到与各类条目的打开方式（在网盘中显示、在新标签页打开、外部播放器、
  解压、恢复到网盘）以及固定到快速访问；下载指定段落、查找重复、归档、取消归档、预览遮蔽、来源链接在操作面板里
  收进「更多」，右键菜单里按组平铺在列表中。
  取消归档只在文件夹挂着归档标记时给；归档一直给，挂着标记的文件夹里仍可能有没归档的（跳过的小文件、后来放进的）。
  「移除记录」（最近添加、播放历史）与移入回收站同在末组，图标是减号圈，不用垃圾桶。
  省略号只加在点了还要先挑目标或参数的项上（移动到…、复制到…、下载指定段落…）。「下载」不加，理由见下一条。
- 下载与画质：没有单独的「选择画质下载」（原先在「更多」里，播放器那一排叫「画质」，用户看不懂），画质在点「下载」时选。
  所有下载入口（单项与多选的面板和右键菜单、命令栏、移动端多选栏、播放器设置面板）都经 `components/DownloadLauncher`，
  不在各处判断。所下的项里有没借出的视频或文件夹时弹 `DownloadQualityDialog`，默认选中设置里的下载画质，一次确认即下；
  只有别的文件、归档条目或压缩包里的文件（只有原画）时直接下。单个视频列出各档与大小（逐档探测，先列档位后补大小，
  菜单项上按下或悬停时就开始查）；几项一起只列级别，每个视频各自挑不高于它的最高一档，规则见 `shared/.../download/CLAUDE.md`。
  对话框里可勾「以后按此画质直接下载」，即关掉设置里的「下载前选择画质」并存下所选级别。
  比较过反过来的做法：默认按设置直接下，只在长按或另一项「下载…」时问。否决：桌面菜单项没有长按，另加一项就回到了两项并列；
  而按设置的上限直接下又让选画质这件事藏起来，没设过上限的人不知道能选。现在多数情况一次确认，嫌烦的勾一下就不再问，
  所以「下载」不算「还要先挑参数」，不加省略号；同一项的名字也不该随选的是不是视频而变。
- 属性（`PropertiesPane`），照资源管理器的「属性」、Finder 的「显示简介」：右键菜单与操作面板末尾单独一组「属性」，
  空白处右键的「属性」看当前目录；主修饰键+I（mac 上 ⌘I），Windows 与 Linux 另有 Alt+Enter。看的是打开那一刻的那一项，
  几项时是项数、合计大小与所在位置，之后选中怎么变都不跟。宽窗口（标签栏同此条件）是浮在列表上的卡片，外壳与目录图同为
  `FloatingPanel`，不挡着继续操作列表，与信息流、目录图可以同时开着；一次只开一个，对别的项再开就换掉内容。窄窗口是面板（`PikoSheet`）。×、Esc 关闭。
  卡片出现在触发它的地方（`PanelAnchor`，位置经 `PropertiesAnchors` 取）：右键菜单点的放在右键按下处，同右键菜单的翻转规则；
  操作面板、Alt+Enter、主修饰键+I 贴在那一项旁边，先右后左，多选时以焦点项为准；命令面板与当前目录放在列表中央偏上。
  已开着时换内容不挪位置，只在放不下时夹回列表里；可以拖着挪，关掉再开按新的触发点放，位置不存。
  照 Windows 的属性窗，大小不给改：宽度随内容（280 到 440dp），高度随内容，超出列表就在卡片里滚。有缩略图的文件才有预览，
  别的是图标加名字一行；属性表的标签列按最长的标签对齐，长的值换行。
  否决过的形态：常驻、跟着选中走的详情栏，先是推开列表的侧栏（开合时网格重排，与信息流抢右侧那一栏，开详情就挂起信息流），
  后是浮窗（仍挡着列表，要看的往往只是某一项的几行属性）；条目上悬停出现的详情按钮也随之去掉。桌面的条目上不画按钮，
  移动端是打开操作面板的更多按钮（曾按宽度判断，平板横握两样都没有，单项操作不可达）。
  以后刮削到的作品信息放在预览与属性表之间。
- 名字：一项可能有两个名字，解析出的显示名（文件夹「动画」认作「Frieren」、集号「01」、结果页的规范名）与网盘里的真实名称。
  认条目的地方用显示名，真实名称另起一行小字写在下面，只在两者不同时：海报墙、列表、图库（没封面的文件夹）、操作面板头部、
  属性卡片，以及提到「哪一项」的拖放说明、下载片段面板、归档对话框与归档的进度和结果。标路径的地方一律用真实名称，
  `FolderIndex` 与存下的路径不动：地址栏、标签、移动端标题、目录选择器、目录图、重命名框（预填真实名称）、库与搜索结果的位置一栏、
  拖放与移动、复制的目标文件夹、查重与规范命名的起点（它们开成标签）。
  单一来源是 `DriveItemName`（`shared/.../state/DriveItemName.kt`）：卡片经 `driveItemName` 从行的 `DriveFileView` 与文件夹的
  `DriveFolderView` 取，别处经 `DriveScreenState.itemName`，同一份输入，不要再写 `folderViews[id]?.title ?: name`。
  行与卡片用 `title`（集号不带作品名，作品头里已有），面板、属性与提示用 `heading`（「Frieren 01」）；怎么摆见 `ItemNames.kt`。
  解析关闭时一律真实名称；结果页的标题（查重是原名、规范命名是新名）不是解析结果，不随开关。
  目录内搜索两个名字都认（`listedName`：搜索结果平铺、行上没有解析结果，按这个目录不搜索时的名字匹配）。
  全盘搜索仍只认真实名称：遍历在 SDK 的 `searchFilesRecursive` 里按名字过滤，文件夹的显示名要等列出它的内容才算得出，
  要做得让 SDK 交出每层的列表、由 Piko 匹配，文件夹在列出它自己那一层时才报出，最深一层的文件夹认不出。

## 鼠标与键盘

网格的空白处另有一层右键菜单（查看、刷新、粘贴、新建、全选、属性），条目的菜单在里层先接住。
点击与键位照各自系统的文件管理器（Windows 照资源管理器，mac 照 Finder），不自创：
鼠标单击是选中（条目取得焦点，`focusIndication` 盖一层底色），双击才打开；触屏轻点照旧打开。
长按在移动端进多选，在桌面弹右键菜单（触屏与笔；鼠标按住不进多选），菜单里的「选择」进多选，见 `ui/CLAUDE.md`。
多选时条目上画着勾选框，鼠标单击照旧是勾选。按住主修饰键点选是加选，
Shift 点选是连选（`selectionClicks`，状态在 `DriveScreenState.toggleSelected` / `selectRange`）。
这几个桌面手势与框选交给状态的是行的 key（`DriveListItem.File.key`），不是文件 ID，由 `DriveScreenState` 换成行上的文件；
平常两者相同，查找重复里不同。网格里读到的 key（`visibleItemsInfo`）同理，不要直接当文件 ID 用。
在网格空白处拖动是框选（`marqueeSelection`，`selectBoxed`），空白处单击退出多选。
全选（主修饰键+A、命令栏、命令面板、空白处右键）与框选一样进入多选。是否在多选里由选中集合推出（`isSelectionMode`），
入口只管改选中的文件，不另置标志；唯一例外是移动端长按进来的多选，取消到一项不剩仍留着。按在已选中或刚点过（焦点所在）的条目上拖动是拖放移动，
按在空白或别的条目上拖动是框选，照相册的做法：海报墙与图库几乎没有空白可按。拖放移动：
拖到侧边栏的文件夹、路径栏的上级或网格里的文件夹上，按着 Ctrl（mac 上 ⌥）是复制。拖放是应用内自己做的
（`FileDragState`，根上一份，落点经 `fileDropTarget` 登记范围），不走平台拖放；拖出去的一批自带落下后做什么，
落点只提供文件夹。
移动、移入回收站与重命名做完都记进 `DriveChangeJournal`（`driveRepository.changes`），提示带「撤销」，
Ctrl+Z 撤销最近一次；以后的批量改动（自动重命名、按刮削结果整理）也记一条，撤销即反向再做一次。

键盘：方向键在条目间走（焦点所在的一项由 `focusIndication` 描边，键盘导航时描边、鼠标点的盖底色，
输入方式由根上的 `trackInputModality` 记），菜单键或 Shift+F10 打开操作面板，
Delete 与 F2 作用于焦点所在项或选中的几项；鼠标点到哪一项，键盘就从哪一项接着走。鼠标侧键是后退、前进。
快捷键见 `DriveScreen` 的 `handleShortcut`。
主修饰键加滚轮缩放视图（`zoomOnWheel`，两端接鼠标都有），沿 `列表 → 海报墙小 → 中 → 大` 逐档走，两端停住；图库不在链上
（只列有缩略图的，滚进去文件像是没了），人在图库里时只在它自己的三档间走。档位见 `DriveZoom.kt`：海报墙与图库各存一份卡片大小，
每台设备各自的，不同步；视图本身照旧同步。每一步从偏好读出当前档再写下一档、前后串起来，不拿界面上的值算，一帧里连来几格才不会只走一步。
命令栏的视图菜单与窄窗口列表页眉都能直接挑大小，给触控板与触屏用。Windows 把触控板捏合当作按着 Ctrl 的滚轮发来，所以捏合也能缩放；
macOS 的捏合是 AWT 不交给 Compose 的放大手势，没有。
Windows：Enter 打开，Alt+Enter 属性（条目自己在 onPreviewKeyEvent 里接住），Backspace 与 Alt+←/→ 后退、前进，Alt+↑ 上一级。
mac：⌘↓ 打开，回车改名（条目自己在 onPreviewKeyEvent 里接住，否则条目的单击先把它当打开），⌘[ ⌘] 后退、前进，⌘↑ 上一级。
